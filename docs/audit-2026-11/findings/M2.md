# M2 — Mapgen wp40: water, roads, vegetation (verified)

- Finder model: claude-opus-5-5
- Verifier model: claude-opus-5-5
- Files read in full: 14 of 15; skimmed: `wp40/wreck_shapes.lua` (generated shape data, header and structure read); not reached: none
- Summary: The package is in good shape on determinism: every `pairs` over output-relevant data is sorted or only fills sets/maxima, no `x ^ 2`, no unseeded randomness, integer fixed point where it matters, and the two world-wide planners (`road_layout.lua`, `water_layout.lua`) run only on main and are stored in the world-folder layout cache (`layout_cache.lua`), so their build cost is first-boot only. The real per-chunk cost sits in the two per-column samplers: the water sampler's `river_at` walks every segment within a fixed 160-node reach (from the constant `R_MAX = 110`) with a `sqrt` each and then runs the `exp` blend even for columns whose result is thrown away, and the road sampler's `column` walks ~90 segments per road through nested table lookups. Both can be made cheaper with byte-identical output. Beyond that: duplicated integer lattice noise in at least three modules (plus four `mix` variants), duplicated polyline/heap helpers between the two layouts, a handful of dead exports, and stale comments in `road_layout.lua`. `treegen.lua` and `vegetation_density.lua` do not run per mapgen column (the brief's assumption): treegen runs per template variant at load and per sapling growth, vegetation_density per runtime renewal sample.

## Findings

### M2-01 | Medium | perf | Water sampler: every column within 160 nodes of a river walks all bucket segments and blends with `exp`, even when the result is discarded

- **Verdict:** CORRECTED — the cost is as described (`water_layout.lua:2027` REACH = 110 × 1.15 + 34 = 160.5 with `R_MAX = 110`, `TROUGH_WOBBLE = 0.15`, `BLEND_K = 8`, `terrain_data.lua:279-281`; registration `:2076-2083`; `river_at` `:2113-2157`; use condition `:2185`, else `d = nil`), and the only callers are `height.lua:675` (water.column, which reads `id` only with `water_y`, `:678-681`) and, for the bucket lists, `maybe_wet` (`height.lua:1715`, `placement.lua:238,276`). But **step 1 as written is not byte-identical.** A column is used not only when `t < 1` (needs `dmin < R·(1+WOB·nwall)`) but also when `d <= wl + BANK_REACH` with `BANK_REACH = 30` (`terrain_data.lua:290`); such a column blends every listed segment with `d < dmin + 4K`, so identity needs every segment within `max(Rmax·(1+WOB·NWALL_MAX), WLmax + BANK_REACH) + 4K` of the column to stay listed. The finder's bound `Rmax·(1+WOB) + 4K + 2` drops the `WLmax + 30` term: since a vertex's wet limit is `min(R, w + 6) + 2` (`:2042-2044`), `WLmax + 30` exceeds `1.15·Rmax` whenever Rmax is below about 200, which is always (R is clamped to 110); e.g. Rmax 40, WLmax 30: bank columns up to dmin 60 need segments to 92, the new lists guarantee only 80. Segments that fall out of a list change `sW`, `sR`, `sWL`, `lown` of such columns. With the corrected bound the proof goes through (a dropped segment lies beyond `dmin + 4K` of any used column, list order is a subsequence so sums and the first-minimum tie rule are unchanged, `dwet` only matters within 6 nodes, and `maybe_wet`'s `wl + 4K + 1` stays inside the list). It saves something only on seeds whose layout keeps every R below the 110 clamp. **Step 2** is sound in exact arithmetic (blended R and wet limit are convex combinations, then only lowered by `f <= 1` and the step clamp at `:2201-2203`; the tie directions `>=` against `t < 1` and `>` against `<=` are right), but floating point can put `sR/sw` or `sWL/sw` a few ulps above the maximum and `d / (R·k) < 1` is not the same rounding as `dmin >= Rmax·k`; skip only with a relative margin (for example `(1 + 1e-9)` on both bounds). `NWALL_MAX` must be derived, not assumed: the simplex is scaled by `SCALE = 99.2` (`terrain_field.lua:71`), which is not an analytic bound of 1; an over-estimate is free for identity. Only `seg` (4th return) changes from an index to nil on skipped columns, which `height.lua:678-681` never reads without `water_y`. **Upgrade class:** `water_layout.lua` is in the preparation-authority digest (`preparation_identity.lua:10-13`, used through `r7_runtime.lua:552` → `starts_preload.lua:110-112`), so any byte change stops a world in `full` preparation mode at its next start ("Surface preparation authority changed"), also after preparation finished (the check runs whenever `state.total` exists); `docs/technical/upgrade-contract.md:604-606` states the rule. Byte-identical output does not make this a compatible upgrade for such worlds; it needs an authority-migration step or a ruling. The layout-cache key (whole mod tree) also forces one layout rebuild at the next boot.
- **Where:** `mods/MAPGEN/grug_mapgen/wp40/water_layout.lua:2025-2027` (REACH), `2076-2083` (bucket registration), `2113-2157` (`river_at`), `2177-2228` (`api.column` use condition)
- **What:** Every segment is registered in every 32-node bucket within `REACH = P.R_MAX * (1 + WOB) + 4 * K + 2` = 110 × 1.15 + 32 + 2 = 160.5 nodes, a constant from the clamp `R_MAX`, not from the layout's actual trough radii. With `SEG = 8` a bucket list holds about 44 segments per river that passes within ~160 nodes (more near confluences). `river_at` computes a `sqrt` for every listed segment, then for every column with `dmin <= REACH` runs the blend loop with one `exp` per segment within `dmin + 32` (about 8 to 16 segments). `api.column` then uses the river values only if `t < 1 or d <= wl + P.BANK_REACH` (line 2185). So every land column in a band of about ±160 nodes around every river pays the full cost, and most of them, beyond about `wl + 30` and outside the trough radius, discard the result.
- **Evidence:** `height.lua:665-691` calls `water.column(x, z, h0)` once per land column per Lua state (memo block), in main and in emerge, so this runs for every land column of every generated chunk. `river_at` has only one caller, `api.column`: `rg "river_at\(" mods/` finds only `water_layout.lua` (the `planner.lua` and `r6_settlement.lua` hits are local functions named `wet_river_at`). `water.column` has only one caller (`height.lua:675`). That caller uses the 4th return value (`id`) only when `water_y` is set (`height.lua:678-681`).
- **Proposal:** Three steps, each byte-identical for every caller.
  1. Build `REACH` from the deserialized layout: `max(Rmax * (1 + WOB * NWALL_MAX), WLmax + BANK_REACH) + 4K + 2`, with `Rmax = max(SR0, SR1)` and `WLmax = max(SL0, SL1)` over all segments, capped at the current constant (verifier correction: the finder's `max(SR0, SR1) * (1 + WOB) + 4K + 2` omits the bank-reach term and is not byte-identical). On seeds where no trough reaches `R_MAX` the lists shrink.
  2. In `river_at`, after pass 1, take `Rmax = max(SR0, SR1)` and `WLmax = max(SL0, SL1)` over the segments with `d < dmin + 4K`. If `dmin >= Rmax * (1 + WOB * NWALL_MAX)` and `dmin > WLmax + BANK_REACH`, return nil before the `exp` loop. The blended R and wet limit cannot exceed these maxima, so `api.column` would not have entered its branch. Only the unused `seg` return changes.
  3. Optionally, a regional bound per 256-node region (the max reach term over segments within `REACH + 4K` of the region) to shrink the lists further.
  Keep the summation order and the tie rule of `best` (first index of the minimal `d`) unchanged. Confirm the range of the `river_wall` simplex before using `NWALL_MAX = 1`.
- **Effort:** M · **Risk:** low · **Upgrade class (verifier):** output byte-identical with the corrected bound and margins, but `water_layout.lua` is in the preparation-authority digest: not compatible for worlds in `full` preparation mode without an authority-migration step
- **Measure:** Unmeasured. Seed 12345, the 640 × 640 area round a river confluence. Count list lengths and the share of `river_at` results that pass the `api.column` use condition. Time `water.column` over every land column before and after. Then compare the chunk digest (`tools/seed_fleet`) for byte identity.
- **Confidence:** medium (the cost is certain; the gain depends on the measured list lengths and R distribution)

### M2-02 | Medium | perf | Road sampler `column`: ~90 segments per road walked per column through nested table lookups, with a `sqrt` each

- **Verdict:** CONFIRMED — `road_layout.lua:2372-2507` reads as described: segments of 1 node (`resample(pts, 1)`, `:1315` and others) registered in every 32-node bucket within `hw + SIDE_MAX + 1` (`SIDE_MAX = 24`, `:107`), and per listed segment a decode, five to eight hash lookups and a `sqrt`; the only caller is `height.lua:1597-1599` (`road_at`). Byte identity of the prefilter holds, ties and boundaries included: a skipped segment has `e = d - hw > SIDE`, while any segment that can make the answer non-nil has `e <= SIDE`; so the minimum `e` and its first index (strict `e < best`) are unchanged whenever some segment has `e <= SIDE`, and when none has, the original also returns nil (`cut_cap = INF`, `fill_floor = -INF`, no surface since `best > 0`, `:2490-2506`); `d2` uses the same `rx, rz` as `d`, and the `1e-9` relative margin is far above rounding at `hw + SIDE ≈ 28`. Flattening keeps identity if the arrays hold the same numbers and the neighbour classes keep their nil at road ends (`r.cls[i - 1]` at `i = 1` is nil, which counts as interior, `:2416-2423`). The `extra` table is allocated only for surface columns (`best <= 0`), not every column near a road. **Upgrade class:** `road_layout.lua` and `height.lua` (the `extra` change touches `road_at`) are both in the preparation-authority digest (`preparation_identity.lua:10-13`; check at `starts_preload.lua:110-112`, rule in `docs/technical/upgrade-contract.md:604-606`): any byte change stops a world in `full` preparation mode at its next start, so "compatible" holds only for worlds not in full mode, unless an authority-migration step comes with it.
- **Where:** `mods/MAPGEN/grug_mapgen/wp40/road_layout.lua:2372-2507` (`M.sampler`, `column`), `2475` (per-column `extra` table)
- **What:** Segments are 1 node long and are registered in every 32-node bucket within `hw + SIDE_MAX + 1` (about 28.5 nodes), so one road crossing a bucket lists about 32 + 57 ≈ 89 segments. For each one, every column does `floor(code / 65536)`, `roads[rid]`, `r.X[i]`, `r.Z[i]`, `r.X[i + 1]`, `r.Z[i + 1]`, `r.cls[...]`, `r.hw` (hash lookups on the road table) and a `sqrt`. A segment whose edge distance `e` exceeds `SIDE` contributes nothing to the answer. If every segment has `e > SIDE`, the function returns nil anyway: `cut_cap = INF` and `fill_floor = -INF` (lines 2490-2506). The water sampler already uses flat arrays (`SAX`, `SAZ`, …) for the same pattern. Every surface column also allocates an `extra` table (line 2475).
- **Evidence:** `height.lua:1597-1599` (`road_at`) calls `road_sampler.column` from the per-column final values, once per column per Lua state, in main and in emerge. `road_exclusion_at` (`height.lua:2109-2124`) adds a `near` scan per column. Columns far from roads return at the nil-bucket test (line 2399), so the cost falls on columns within about 60 nodes of a road.
- **Proposal:**
  - Flatten the segments into arrays at sampler build: ax, az, vx, vz, l2, the road's hw and R, and the cls of i-1, i, i+1, i+2.
  - Skip a segment without a `sqrt` when `d2 > (hw + SIDE)^2 * (1 + 1e-9)`. The margin keeps the exact `e <= SIDE` test for borderline cases.
  - Return the `extra` fields as plain values; this needs `height.lua`'s `road_at` changed in step.
  Keep the iteration order (the bucket order) and the strict `e < best` tie rule. Output stays byte-identical, including the nil answers.
- **Effort:** M · **Risk:** low · **Upgrade class (verifier):** output byte-identical, but both touched files are in the preparation-authority digest: not compatible for worlds in `full` preparation mode without an authority-migration step
- **Measure:** Unmeasured. Seed 12345, a chunk column with a primary road junction plus a capital street chunk. Time `road_sampler.column` over 80 × 80 columns before and after, then check the chunk digests for byte identity.
- **Confidence:** medium

## Backlog notes

- `wp40/water_authored.lua:64`: the permutation LCG `state * 1103515245` reaches about 2.4e18, above the 2^53 rule (luanti-lua.md checklist 5). It is still deterministic (IEEE products, and `% 2^31` is exact on doubles in every build), but changing it would reshape the authored lakes (map reset). Keep it and add a comment naming the exception.
- `wp40/water_layout.lua:1845`, `1857-1882`: `wet_core` guards the built layout at full precision, while the samplers read the `%.1f`/`%.2f` serialized text (1919-1920). A core that the build passes by under 0.05 nodes could stand in water after rounding. This is theoretical; it could be guarded on the deserialized layout instead.
- `wp40/road_layout.lua:2640`, `2114`, `2660`: the road build sorts string anchor ids with `<` (locale `strcoll` under PUC, byte order under LuaJIT). The ids share the prefix `anchor_`, the build runs only on main and is cached, so there is no divergence today. `less_bytes` would make this robust.
- `wp40/road_layout.lua:1521-1556`: `update_ndist` re-runs a full 196k-cell chamfer after every committed non-trail road. `road_check` (2120-2145) rebuilds a hash of all roads for each loop candidate. The start branch calls `nearest_idx` per point (1745-1751), which is O(n·m). All of this is first-boot build cost, cached in the world folder.
- `wp40/height.lua:2136`, `wp40/r7_runtime.lua:714`, `wp40/wayposts.lua:128`, `wp40/world_protection.lua` (road corridors): main deserializes the same road text 3 to 4 times at load. A shared decoded layout would save that load-time work.

- `wp40/swamp_writer.lua:94` and `124-126`, `144-146`: `pools.at` is not memoised and is called up to 5 times per swamp column, each a `noise` call when kept. The cost is small.
- `wp40/wreck_writer.lua:324`: the tools hook `rawget(_G, "GRUG_WRECK_LAYOUT_HOOK")` is in shipped code. It is harmless and read once per construction.
