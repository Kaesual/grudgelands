### X1-01 | Low | edge | grug_sounds.play would send a sound for a removed ObjectRef to every player, unpositioned (no current caller reaches it)

- **Verdict:** CORRECTED — the engine path is exactly as described, but none of the named callers (and none of the other 70 call sites) passes a removed object: the projectile target is re-validated in the same `on_step`, death sounds play before removal, the engine drops punches on gone objects, and no object-targeted call is deferred through `core.after`. Severity stays Low (a cheap defensive guard); it is not raised.
- **Where:** `mods/CORE/grug_sounds/init.lua:326-352` (`target_key` :326-330, `params.object = target` :349)
- **What:** `target_key` treats anything with `get_pos` as an object. For a removed or deactivating entity, or a stale ref of a player who left, `is_player()` is false, so the call sets `params.object = target`. The engine then ignores the object, leaves the sound `Local`, and sends it to every connected client at its full spec gain with no distance check.
- **Engine evidence (checked):** `src/script/lua_api/l_server.cpp:506-520` `l_sound_play` → `read_server_sound_params`; `src/script/common/c_content.cpp:1349-1357` sets `type = Object` only when `ObjectRef::getobject` returns a SAO, and `l_object.cpp:38-44` returns nullptr when `isGone()` — which is `m_pending_removal || m_pending_deactivation` (`src/server/serveractiveobject.h:218-219`), so an object being unloaded counts too. `type` stays `Local`; `Server::playSound` (`src/server.cpp:2334-2373`) gets `pos_exists == false`, which matches `Local`, so it does not cancel; the distance test at :2368-2371 is skipped and every client with a PlayerSAO is added. `is_player` is false for a gone object (`l_object.cpp:1129-1135`, via `getplayer` → `getobject`).
- **Caller trace (verifier):** `rg "grug_sounds\.(play|stop)\("` gives 70 call sites; the object-targeted ones:
  - `grug_projectiles/init.lua:371` (`hit.target`): `settle_hit` is reached only from `on_step` :439-443 right after `grug_core.homing_step` (`grug_core/homing.lua:44-47`), which returns nil unless `identity(lock.target)` holds, and `identity` (:11-21) needs `object:get_pos()` (nil for a gone object) and a live luaentity with health > 0 or a live, connected player. The sound plays before `def.on_hit` deals damage. A second Arrowfall arrow in the same step meets the already-killed target as `target_lost` (:435-437), not as a hit. Not reachable.
  - `grug_abilities/scout.lua:149`: inside the same `on_hit`, before `deal_ability_damage` (:154). Not reachable.
  - mobs `api.lua:318` (`mob_sound`): the death sound is played at :1037, before `remove_mob` (:1061-1086). Other voices run from the mob's own step; the engine does not step gone objects (`src/server/activeobjectmgr.cpp:180`).
  - mobs `api.lua:3439` (hit sound in `on_punch`): the engine refuses player punches on a gone object (`src/network/serverpackethandler.cpp:1013,1151,1165`), and `ObjectRef:punch` on a gone ref is a no-op.
  - `grug_mobs/telegraph.lua:75`, `bosses.lua:610`, `boss_dragons.lua:697,712`, `grug_mounts/entity.lua:418,621`: all `self.object` from the entity's own step.
  - Delayed sounds: the only `core.after` sound call is `grug_jobs/station_sounds.lua:62`, with a position. `grug_home/travel.lua:217,336` re-fetch the player by name (:166-167, :178) and :217 also checks `get_pos`. `grug_mounts/entity.lua:248` is a `stop`, which sends nothing.
  - Player targets (`death_messages.lua:151`, combat, traders, quests, ...) are live players inside their own callbacks.
- **Proposal:** in `play` only, return false when `object and not target:is_valid()` (5.18 has it, `l_object.cpp:119`; the game already uses it, e.g. `grug_core/combat.lua:37`, `tag_carrier.lua:95`). Live targets behave exactly as now. `stop` needs no guard: it only fades a stored handle. This is a guard against a future caller (for example a sound in a `core.after` with a stored ref), not a fix for a current bug.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Confidence:** high (engine path and all 70 call sites read).

### X1-02 | Low | docs | The atmosphere switches also turn off the ambience's Battlegrounds, dragon-island and ocean beds

- **Verdict:** CONFIRMED — `atmosphere_zones.lua:586` returns before the driver exists when either switch is off, `get_atmosphere` (`atmosphere.lua:271-273`) then returns nil, and `R.sound_key` (`rules.lua:75-86`) takes an override only from the mood; the thunder call is keyed on `dragon_island` (`data.lua:246-247`); the ocean survives via `biome == nil` (`rules.lua:79`). `settingtypes.txt:15-29` describe sky, fog and light only; `sound.md:229-230` says the pass reads the mood but not what happens when the switches are off.
- **Where:** `mods/CORE/grug_ambience/init.lua:686-687`, `rules.lua:75-85`; `mods/CORE/grug_core/atmosphere_zones.lua:586-591`, `atmosphere.lua:271-273`; `settingtypes.txt:19,29`
- **What:** The ambience takes its zone overrides from `grug_core.get_atmosphere(name)`, the mood the atmosphere driver applied. With `grug_atmosphere_enabled = false` or `grug_atmosphere_zones = false` the driver never runs, so no mood is set. The Battlegrounds and dragon islands then play their biome group's bed instead of their own, and the dragon-island thunder call (`data.lua:246-247`, keyed on `dragon_island`) never plays. The open ocean survives through the ownerless-column rule (`data.lua:101-104`). The settingtypes texts describe both switches as lighting and sky only. sound.md and the module guides do not mention the coupling. Verifier addition: the reverse also holds — with zones off, an admin's manual `/atmosphere battlegrounds` (which still works, `settingtypes.txt:26-27`) sets `applied[name]` (`atmosphere.lua:312`) and so switches that player's ambience bed to the Battlegrounds bed wherever they stand.
- **Evidence:** `atmosphere_zones.lua:586` (`if not (grug_core.atmosphere_enabled and zones_enabled) then return end`, before the driver registers anything); `atmosphere.lua:271` (`get_atmosphere` returns `applied[name]`, which stays nil); `init.lua:687` (`if not MOODS[mood] then mood = nil end`); `rules.lua:77` (overrides apply only from the mood).
- **Proposal:** decide which side is right. Either the ambience takes the override from the zone itself (the zone id is already in `column.zone_id` from `depth_below_surface`), or the two settingtypes texts add "also drives the zone ambience beds". The beds must stay the same with the switches on.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Confidence:** high

## Good to know

- **Sound handles on leave:** grug_ambience drops a leaving player's state without stopping its loops. That is correct: the engine removes the departing peer from every playing sound in `Server::DeleteClient` (`src/server.cpp:3160-3170`). The music push callback is guarded by `states[player_name]` (`init.lua:614-615`).
- grug_ambience's layer rules never fade a kept handle to 0. A sound at level 0 sits at `LEVEL_FLOOR` until it is stopped (`rules.lua:288-299`), so the engine's erase on fade-to-0 (`server.cpp:2424-2442`) cannot strand a handle the code still uses.
- grug_text cannot be texture-injected: player text becomes code points, and glyph names come only from the `[%w_]+` charmap (`layout.lua:146,164`). Its entities are `static_save = false` and live while their block is loaded (`serverenvironment.cpp:1682-1685`), as its header says.
- **grug_perf against the contract:** the fields, their order, types, optional fields (rtt and jitter absent with no samples), rounding, the 4096-byte limit, spike spacing and the per-step cost all match platform.md "Performance log lines". The profile save matches the engine's `/profiler` func and file naming (`builtin/profiler/init.lua:31-45`, `reporter.lua:225-268`).
- **One-global rule:** no extra global found. Top-level assignments in grug mods are the mod tables, `grug_items` (grug_quality) and `grug_zones` (rawset, grug_core). The other 26 top-level assignments (`tick`, `hud_update`, `flush`, ...) are forward-declared locals. Assignments inside functions are left to `tools/check_lua.sh`'s SETGLOBAL listing, which this audit could not run.
- grug_mobs' three `mobs.mob_class.on_deactivate` replacements (`init.lua:24`, `start_npcs.lua:1173`, `liveness.lua:158`) each chain to the previous one.
- **Locales:** none of the 54 grug mods has a `locale/` folder or calls `core.get_translator`, so all game text is English (ROADMAP.md:256 plans localisation). Only vendored mods translate: 11 BASE mods with about 22 languages each, and the mobs fork with 14. A non-English client therefore sees a mix: vendored item names translated, everything grug untranslated, and patched default strings partly untranslated.
- `minetest.conf`: every entry has a reader, either the engine (mapgen tuple, liquid fluidity, the client render switches), the mobs fork (`mob_active_limit`, `mob_nospawn_range`, `remove_far_mobs`, `mobs_can_hear`), or grug code (`grug_prepare_full_world`, `grug_map_quality`, `num_emerge_threads` through `r7_runtime.lua:110`). `game.conf` holds only engine keys plus `version`, which help.lua reads.
- (Verifier) The defensive projectile path: `grug_core/homing.lua:11-21,44-47` re-checks the target's liveness every step, which is why X1-01 has no current caller.
