### M5-01 | Medium | persist | The documented full-preparation byte rule has no gate: a "compatible" release can stop full-mode worlds without a map reset entry

- **Verdict:** CORRECTED — the mechanism holds (`starts_preload.lua:92`, `:110-112` asserts for every full-mode world with a plan, no `ready()` test; the 27-file list at `preparation_identity.lua:252-263`), but it is a documented, decided rule, not a defect: the design says "A mismatch stops preparation with a restoration message; there is no fallback volume, old-plan reader or migration" and "changed terrain or selection semantics reject reuse" (`docs/design/world_preparation.md:186-193`, also `:69-71`), and the upgrade contract states the byte rule (`docs/technical/upgrade-contract.md:604-606`) and calls "compatible" only a best-effort intent for full-mode worlds (`:18-20`). Full mode is opt-in (`settingtypes.txt:75`, `minetest.conf:200`, default false; the hosting platform uses `starts`). No tool checks it (`tools/check_upgrade.py:18-30` compares the version, the lists and what the towns build; `tools/check_fresh_server.py` has no digest; no fixture pins `grug_surface_v1`). History: comparing the 27 files between consecutive release commits of `game.conf` found no unannounced break. 0.57.0 (compatible) changed `zones.lua`, `zone_field.lua` and `simple_map.lua` (`73d43d3a6`, FIX56), and its CHANGELOG told admins that full-mode worlds refuse to start until a map reset (`CHANGELOG.md:1078-1082`). The 0.69.0 commit `995a3ce9c` put `camp_sites` into `r7_runtime.lua`, and the same day `7a1b3abad` ("out of the preparation authority") moved it out before 0.70.0. Every other change fell in a release with a `map_reset` entry (`tools/web_data/upgrade.json`). Nothing digested changed since 0.75.5. The rule holds today, but only because authors and reviewers remember it. Severity: Medium (a hard boot stop on a rarer, opt-in path, guarded only by hand); not High, because no concrete undeclared case exists.
- **Where:** `mods/MAPGEN/grug_mapgen/wp40/preparation_identity.lua:251-272`; `mods/MAPGEN/grug_mapgen/wp40/r7_runtime.lua:548-553`; `mods/MAPGEN/grug_mapgen/wp40/preparation_source.lua:63-71`; `mods/CORE/grug_core/starts_preload.lua:79-87,92-112`; rule text `docs/technical/upgrade-contract.md:18-20,604-606`, `docs/design/world_preparation.md:69-71,186-193`; missing gate `tools/check_upgrade.py`
- **What:** The preparation identity is a SHA-256 over the whole-file bytes (comments included) of 27 files. It is combined with the seed, the WP43 material projection digest and the four layout texts, then hashed with the template reach and every settlement/anchor box. `initialize()` asserts `state.authority == source.identity` for every full-mode world with a plan, finished or not, so a mismatch stops the server at every start until the old files come back or the map is reset. The project decided this rule and wrote it down. It is enforced only by hand: a round that edits one of the 27 files (even a comment), a digested `grug_materials` field or a settlement box in a release without a `map_reset` entry must remember the CHANGELOG admin note, as 0.57.0 did. `check_upgrade.py` would not notice if it forgot.
- **Evidence:** as in the verdict. `starts_preload.lua:110-112` `assert(state.authority == source.identity, "Surface preparation authority changed; ...")` sits in the `else` branch of `if not state.total` (`:92`). A map reset keeps only the mode (`starts_preload.lua:7-13`, contract §3.2 table line 142), so a map reset release is safe.
- **Proposal:** Add a gate to `tools/check_upgrade.py`, next to the town comparison and with the same base (`--base`, default `origin/main`). Read the file list from `preparation_identity.lua` at both commits. Hash the listed files' bytes at both commits (the WP43 projection inputs too, if that can be done cheaply in the tool). When the hash differs, require one of two things: a new `map_reset` entry the pushed declaration did not have, or, for a release declared compatible, an explicit acknowledgement. One form for that: a `grug_prepare_full_world` admin line in the new version's CHANGELOG section, the 0.57.0 practice. Report which files differ. This leaves the identity value, the plan format and the boot behaviour unchanged. The finder's proposals are changes to a documented rule and need the user's ruling before anyone builds them: (a) skip the comparison for a finished plan; (b) start a new plan instead of asserting. Point (a) is plausible because a finished plan never scans again. The gate is useful either way.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible (tool only)
- **Confidence:** high

### M5-02 | Medium | security | Terrain-damage and water guard ignore the road and POI-core protection: player water floods roads and POI, village and camp cores

- **Verdict:** CONFIRMED — duplicate of **C1-01** (`findings/C1.md`), which is the better description and the one to act on.
