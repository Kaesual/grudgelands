# E1 — Traders, projectiles, vendored patches (verified)

- Finder model: claude-opus-5-5
- Verifier model: claude-opus-5-5
- Files read in full: 9 of 9; skimmed: `stock.lua` lines 310-439 (the Decor Merchant price table, data only); vendored trees reviewed at their `GRUG PATCH` sites and `grug_` identifiers only (per brief); not reached: none
- Summary: The trader code is in good shape on the exploit side: every buy, sell, lot sale, trade-in, Stonewright and crown action re-validates session, distance, faction, row and price server-side, money is checked against `grug_money.MAX` before items leave, a full inventory refunds exactly, and equipped, soulbound, bound and quest items cannot reach the sell list. I found no duplication or money path. The most valuable items are a per-step `get_properties` call that each homing projectile makes on its target, the capital offset-slot fallback in `vendors.lua` that serves an empty set (its globalstep still runs), and a stale and self-contradicting `GRUG PATCH` inventory in `VENDOR.md` (four different mobs_redo totals; the real count is 191). Smaller items: dead fields and functions, a Crownbinder window that falls silent instead of closing, stale `mod.conf` depends, and a stale crown fee in the technical doc.

## Findings

### E1-01 | Medium | perf | Every homing projectile reads its target's full property table on every server step

- **Verdict:** CONFIRMED — `grug_projectiles/init.lua:434` calls `grug_core.homing_step` on every `on_step`. `homing.lua:66` ends in `target_center`, which calls `object:get_properties()` (`homing.lua:25`) only for the box. The mob actor projectiles in `grug_mobs/verbs.lua:780` take the same path. In the engine, `ObjectRef::l_get_properties` (`reference_projects/luanti/src/script/lua_api/l_object.cpp:1036-1050`) takes no lock and does no other work. It calls `push_object_properties` (`src/script/common/c_content.cpp:545-651`), which builds a fresh table of about 55 fields with eight nested tables (two boxes, visual_size, textures, colors, spritediv, initial_sprite_basepos, the nametag colours). The cost is all table construction and garbage, per projectile per step. The step is 0.09 s (`builtin/settingtypes.txt:2300`). The proposal's refresh interval is needed: target boxes do change in flight, for a sitting player (`grug_visuals/apply.lua:366`) and for a scaled or grown mob (`mobs/api.lua:452,1534`). For mobs, a cheaper source exists: `self._grug_cbox` (`mobs/grug_obstacle.lua:47`). Medium stands as a clear improvement on a combat hot path; it is not a large server cost.
- **Where:** `mods/ENTITIES/grug_projectiles/init.lua:423-450` (on_step) → `mods/CORE/grug_core/homing.lua:44-67` (`homing_step`) → `homing.lua:24-30` (`target_center`)
- **What:** `on_step` calls `grug_core.homing_step` every server step. That function calls `target_center`, which calls `object:get_properties()` only to read the collision box. `get_properties` builds a new Lua table with every object property (`push_object_properties`, `reference_projects/luanti/src/script/common/c_content.cpp:545ff`, about 60 `lua_setfield`s plus nested tables). In the same step, owner identity is also checked twice: `get_player_by_name` + `get_hp` in on_step (`init.lua:428-430`), then `identity(lock.owner)` in `homing_step` (`homing.lua:12-17`, another `get_pos`/`get_hp`/`get_player_by_name`).
- **Evidence:** Hot path: one call per projectile per server step (`dedicated_server_step` 0.09 s, `reference_projects/luanti/builtin/settingtypes.txt:2300`), for up to 2 s per flight (`homing.lua:39`). There are four mage projectiles and the scout arrow (`grug_abilities/kits_mage.lua:94-155`, `scout.lua:128`), with `active_limit` 4-8 per player and type. A held Loose fires every 0.65 s, and Arrowfall fires four arrows at once. Mob actor projectiles use the same `homing_step` (`grug_mobs/verbs.lua:780`, locks from `homing.lua:81-95`). At 100 players, a few hundred property tables per second is a realistic floor in a busy fight.
- **Proposal:** Compute the box-center offset once in `homing_lock` and store it on the lock (`lock.center = {dx, dy, dz}`). `target_center` then adds that offset to `pos` with no engine call. Target boxes do change: a player who sits (`grug_visuals/apply.lua:366`) or a mob scaled by `scale_mob`. To stay exact, refresh the offset at most every 0.5 s of `lock.age`, or read a mob's cached `_grug_cbox`. The arrival point would differ only for a target whose box changes mid-flight. Optionally, let `on_step` skip its own `owner:get_hp()`, because `homing_step`'s identity check covers it. Keep the session comparison, which `homing_step` does not do.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Measure:** unmeasured. On a larger machine, run a scripted fight: 20 fake scouts holding Loose plus 20 mages spamming Fiery Spark at mobs in one arena. Measure the Lua profiler share of `grug_projectiles` on_step (`/profiler` or `profiler.load = true`) before and after.
- **Confidence:** high (on the call chain; the size of the gain is unmeasured)

### E1-02 | Low | dead | The capital offset-slot fallback in `vendors.lua` serves an empty set, but its globalstep still runs

- **Verdict:** CONFIRMED — All six capital plot files carry one `role = "vendor"` socket (`rg -c` over `wp13/`). `build_slots` (`vendors.lua:617-652`) adds offset slots only for a capital without such a socket. The globalstep (`:710-735`) has no early return on `#slots == 0`: every 5 s it fetches the players and their positions, then loops over zero slots. The emptiness depends on runtime socket data; this verifier did not read the startup log the finder cites.
- **Where:** `mods/ENTITIES/grug_traders/vendors.lua:583-758` (`SLOT_OFFSETS`, `slots`, `socketed_capitals`, `build_slots`, `player_near`, `vendor_present`, the 5 s globalstep) and `:813`
- **What:** The fallback places the two capital traders at fixed offsets around a capital whose core has no `vendor` sockets. All six capitals now export `vendor` sockets, so `build_slots` always leaves `slots` empty. The globalstep still wakes every 5 s, calls `core.get_connected_players()` and `get_pos()` on every player, and builds a position table, then loops over zero slots.
- **Evidence:** `docs/technical/modules/items-professions.md` (Vendor NPCs): "the offsets serve only a capital whose core has not been built — an empty set since all six cores landed". Every capital plot file defines `role = "vendor"` sockets: `rg -n 'role *= *"vendor"' mods/MAPGEN/grug_mapgen/wp13/*_plot.lua` → dur_brannoc, highcourt, gor_drazhak, nhal_veyr, lethariel, kezamba. Startup logs show all six races taking "capital vendors come from the sockets of …" (`tools/r49_v7/evidence/baseline2/server.log:88-93`).
- **Proposal:** Remove the offset fallback (about 170 lines). Keep a startup assertion in its place: `build_slots` raises an error when a capital has no `vendor` socket, which also catches a blueprint regression louder than a silently placed offset vendor would. Minimal alternative: `if #slots == 0 then return end` at the top of the globalstep. Behaviour stays identical either way because the set is empty.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Confidence:** high

### E1-04 | Low | edge | The Crownbinder window goes silent instead of closing when the player is no longer permitted

- **Verdict:** CONFIRMED — `crown.lua:239-241` drops the session on `not permitted` and returns `true`. The file has no `close_formspec` call.
- **Where:** `mods/ENTITIES/grug_traders/crown.lua:234-242`
- **What:** If `permitted` fails (the player walked more than 6 m away, the player is dead, or an admin changed their faction), the handler drops the session and returns. It neither closes the form nor tells the player why. The window stays open. Every later click, including Crown, then hits `not session` (`:238`) and is ignored without a word. The trade window in the same mod closes with "You walked away from the vendor." (`trade.lua:697-700`).
- **Evidence:** `crown.lua:239-241`: `if fields.quit or not permitted(player, session) then sessions[name] = nil return true end`. There is no `core.close_formspec` call in the file.
- **Proposal:** On `not permitted` (not on `quit`), call `core.close_formspec(name, formname)` and send one chat line, as `trade.lua`'s `close()` does.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Confidence:** high

### E1-09 | Low | perf | The potion cooldown status source reads player meta on every status pass

- **Verdict:** CONFIRMED — The status source at `potion.lua:76-79` calls `potion_cooldown_left`, which does `get_meta():get_string` and `tonumber` (`:43-57`). The pass runs every 0.5 s (`grug_core/status.lua:34`). The cost is small: a player-meta string lookup per player.
- **Where:** `mods/ENTITIES/grug_traders/potion.lua:43-57, 76-79`
- **What:** The status source calls `potion_cooldown_left`, which does `get_meta():get_string()` plus `tonumber` for every connected player on each `grug_core` status pass. That pass runs every 0.5 s for all players (`grug_core/status.lua:34, 464-475`), even though the value changes only when a potion is drunk.
- **Evidence:** At 100 players that is about 200 meta reads per second, almost all of which return "ready". Only `start_potion_cooldown` writes the key (`rg -n "grug_traders:potion_cd" mods`).
- **Proposal:** Keep a name → expiry Lua cache. Fill it in `start_potion_cooldown` and lazily on the first read after join, clear it on leave, and keep meta as the persisted copy. Behaviour stays the same, including across relogs and restarts.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Measure:** unmeasured; profile the `grug_core` status globalstep with 100 bots, before and after.
- **Confidence:** medium (the cost is small; worth doing only alongside other status-pass work)

## Backlog notes

- `trade.lua:851` re-checks a single-good sell slot by item name only, not with `ItemStack:equals`. A different-quality stack of the same name moved into that slot between render and click would be sold at its own (correct) price. With the trade form open, the player has no inventory window, so only a pickup merge or a foreign mod could cause this; the price is never wrong.
- `trade.lua:666-668, 697-700`: a session is anchored to the vendor's position at open, not to the entity. If a twin vendor removes itself (`grug_mobs.start_npc_claim`) while a form is open, trading continues for up to 6 m. Harmless, because the vendor definition and faction are re-checked.
- `trade.lua:752-766`: `do_buy` takes the money before the `fits` check and refunds on a full inventory. That fires the money change callbacks (HUD, feed) twice for a refused buy. Checking `fits` first would avoid it.
- `trade.lua:1190-1204`: every scrollbar-only packet still runs the `buy_<i>` and `sell<q>_<i>` string-concat loops, about 130 strings for the Decor Merchant. This is negligible per click.
- `init.lua:46-52`: `FUNCTION_DROPS` is a hand-kept mirror of `grug_mobs/bandit.lua:147-170`. It matches today; a new drop added there would be missed by the audit and not by the game.
- `spawn_one` (`grug_projectiles/init.lua:243-248`): `object:get_luaentity()._grug_lock` would error if on_activate had removed the object. That is impossible with the payload built a few lines above, but `release_active` would leak nothing either way.
- `mods/ENTITIES/mobs/lucky_block.lua` loads only with the absent `lucky_block` mod (`VENDOR.md:1170-1172`). It is vendored dead code, documented.

## Good to know

- Exploit surface checked and clean: fields are dispatched in a fixed order (`trade.lua:1164-1204`); every action recomputes the offer, rows and price and cross-checks the shown snapshot; the money ceiling is checked before items are removed (`trade.lua:801, 872`); lot sales take with `remove_item` over `consume_lists`, the same lists that are counted; Crown uses `take_with_inventory` with `ItemStack:equals` (`crown.lua:116-140`, `grug_money/init.lua:140-182`). Equipment lists are not in `consume_lists` (`grug_inventory/storage.lua:52-59`), so worn gear cannot be sold. Soulbound, bound, quest and the Fallen Crown (`grug_rare_trophy`, `grug_mobs/bosses.lua:294-299`) are on `NEVER_GROUPS` (`prices.lua:125-126`). No duplication by double submit: each submit re-renders and refreshes the session snapshot synchronously.
- Projectiles: lifetime is bounded at 2 s by `homing_lock` (`homing.lua:39`); the owner leaving, dying or respawning ends the flight (session ids, `init.lua:43-65, 428-432`); active tokens release idempotently on hit, unload and rollback; PvP and safe-zone rules are re-checked at impact by `grug_core.deal_ability_damage` ("Impact re-check", `grug_core/combat.lua:1249-1253`). The projectile is `physical = false` and touches no node, so there is no terrain-damage path in this mod. It homes through walls by design once the launch ray had line of sight (`homing.lua:42-43`).
- `docs/design/economy.md` numbers checked by sample against code: tier factors and class values (`price_rules.lua:10, 15`), T1/T6 weapon buy-back 2c / 1s25c, 1-2c supplies unsellable, quality ×3/×6, lot sizes and bulk mc values (`prices.lua:99-119`), the 10% discount on buys only, crown fee 1g 48s. All match.
- Vendored trees: every `grug_` identifier in `mods/BASE/*` sits inside a marked block or a whole-file marker. No unmarked change could be shown. Every BASE mod is used: `beds`, `walls`, `wool`, `xpanes`, `doors`, `vessels` and `stairs` by `grug_mapgen` palettes and depends; `dye` by `grug_jobs/basic_recipes.lua`; `creative` as an optional dependency of `grug_inventory`/`grug_skills`.
- `grug_traders` exports many functions whose only outside users are fixtures under `tools/` (`sells_gear`, `guild_vendor`, `crown_rows`, `crown_apply`, `sell_value`, …). Only `potion_cooldown_left`, `start_potion_cooldown`, `POTION_COOLDOWN` and `register_all_vendor_stock` are used by other game mods.
