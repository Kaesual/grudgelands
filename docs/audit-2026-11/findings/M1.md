- Summary: The package is in good shape for determinism: no `x ^ 2`, no `math.random`, every `pairs` that feeds output is either sorted afterwards or per-key independent, and the only clock read (`zone_field.lua` `os.clock`) feeds a log line. `simple_map.lua` and `source/simple_map.lua` are not duplicates: the first is the horizontal-session mechanism, the second the authored data table both environments load. Upgrade trap: every file of this package except `map_adapter.lua` and `counting_allocator.lua` is in the preparation-authority digest (`preparation_identity.lua`), so any byte edit makes a world **in the opt-in `full` preparation mode** assert at its next start (`grug_core/starts_preload.lua:110-112`); worlds in the default `starts` mode are not affected (verifier: see "Good to know").

### M1-01 | Medium | perf | Validated `deterministic.floor_div` used for plain bucket indexing on the per-column path

- **Verdict:** CONFIRMED — `height.lua:136,198-212,624-625` and `zones.lua:845-846` call `deterministic.floor_div` (`deterministic.lua:71-78`: two `integer()` checks plus `divmod_nonnegative`). Equivalence checked: for every call that succeeds today, `math.floor(v / d)` returns the same integer (see the verifier note below); the call count (~40 per tuple) and the gain were not measured.
- **Where:** `mods/MAPGEN/grug_mapgen/wp40/height.lua:136`, `:198-213` (`add_bucket`, `bucket_at`), `:623-650` (`block_for`); `mods/MAPGEN/grug_mapgen/wp40/zones.lua:845-846` (`logical_biome_at`); also `mods/MAPGEN/grug_mapgen/wp40/index128.lua:615-626` (`footprint_candidates`, called by `zones.lua:996/1009/1024` per column) and `zones.lua:294-311` (`normalize_xz`, run on every `planner_source.column_values_at` call including cache hits, `zones.lua:1576-1592`)
- **What:** `deterministic.floor_div` (`deterministic.lua:71-78`) runs `integer()` on dividend and divisor (seven checks each) and `divmod_nonnegative` (abs, floor, two correction loops) for every call. `height.lua` uses it for the memo-block key (`block_for`, two calls per `column()`) and for every fitting/authored/square bucket lookup (`bucket_at`, two calls each). One cold planner column tuple (`zones.lua:1495-1574`) reaches `column()` through `inland_water_at`, `terrain_height_at` → `final_values_at` → `land_values_at` → `natural_height_at`, `water_surface_at`, `functional_surface_values_at`, the four shore neighbours (`exposed_shore_at`, `height.lua:1506-1528`) and `bucket_at` through `fit_land` (three grids), `in_capital_core`, `square_at`, `core_excess` — on the order of 40 `floor_div` calls per tuple, plus two in `logical_biome_at`, plus the validations of `index128.footprint_candidates` in `hard_row_at`. The inputs are always integers in range (an out-of-range or fractional value would already throw today), so `math.floor(v / d)` returns the same value.
- **Verifier note on equivalence:** divisors are the constants 128 (`FEATURE_CELL`, `height.lua:93`), 80 (`BLOCK`, `:96`) and 192 (`cell_size`, asserted at `zones.lua:574`). Dividends: `block_for` gets `x + 32`/`z + 32` of `column(x, z)`; `logical_biome_at` gets either the normalised integer query point or the clamped `dither_point` result, which is `floor(... + 0.5)` (`zone_field.lua:765-769`), i.e. integer. For an integer `v` with `|v| <= 2^53` and an integer `d >= 1`, the IEEE quotient `v / d` is exact when `d` divides `v`, and otherwise lies at least `1/d` from the next integer while its rounding error is at most `|v/d| * 2^-53 < 1/d`; so `math.floor(v / d)` equals the exact floor quotient for negative and positive `v` alike (the finder's `2^40` bound is unnecessarily tight). The only differences: (1) a fractional or non-number argument raises today and would pass silently afterwards (no `pcall` wraps these paths in `height.lua`/`zones.lua`, so no current behaviour depends on the raise); (2) `v = -0` gives `-0` instead of `0`, which only matters for `tostring`/`1/x`; as a table key LuaJIT hashes `-0` and `0` alike, and these values only feed keys and integer arithmetic. The package already does exactly this in `index128.lua:26-28` (`math.floor(value / CELL_SIZE)`). Coordinates are bounded by the engine (±31,000), far inside the range.
- **Evidence:** callers above; the cold planner (column tuples) is the largest surface-chunk cost after Round 49: "The cold planner remains the largest surface cost: 93–102 ms of A_S1" (`docs/research/mapgen-chunk-profile-2026-10.md:978`) and "a new 80 x 80 chunk column with its halo misses about 7,200 tuples (about 6 us each)" (`zones.lua:1448-1451`). The tuple is computed for every first chunk of a column on every emerge thread.
- **Proposal:** in `height.lua` use a local `floor((v + BLOCK_OFFSET) / BLOCK)` in `block_for` and `floor(v / FEATURE_CELL)` in `add_bucket`/`bucket_at`; the same in `zones.lua:845-846` for `cell_size` 192. In `index128.footprint_candidates` drop `assert_sparse_kind` and the two `integer()` calls on the hot path (keep them in `compile_footprints`), or have `zones.lua` hold the compiled `cells` and index them directly. In `planner_source.column_values_at` take a fast path when `x % 1 == 0 and z % 1 == 0` (then `normalize_coordinate` returns its input) before the full normalisation (the test must stay after a `type(x) == "number"` check; for `NaN` and `±math.huge` the expression `v % 1` is `NaN`, so those fall through to the full path and still raise). Generation output stays byte-identical (same integers everywhere).
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible for output and for worlds in the default `starts` preparation mode; `height.lua`, `zones.lua`, `index128.lua` are in the preparation authority, so a world in the opt-in `full` mode refuses to start until a map reset — ship with the next map reset or name it in the changelog as an earlier water change did (`CHANGELOG.md:1078-1082`)
- **Measure:** unmeasured. Before/after with the `tools/mgprof` stage boots of `docs/research/mapgen-chunk-profile-2026-10.md` (same seed, same corpus chunks): stages "planner R5" and "planner R6 columns" of A_S1 and B_B (cold first chunk of a column), and the warm A_S2 for the hit path; plus `tools/r49_cache` to prove hit equals miss.
- **Confidence:** high (equivalence); medium (call counts and size of the gain)

## Good to know

- **Preparation-authority trap (verified by the verifier; every mapgen proposal depends on it):**
  - *What is digested.* `mods/MAPGEN/grug_mapgen/wp40/preparation_identity.lua:8-30` reads the raw bytes (`io.open(..., "rb")`, `read("*a")`) of a fixed list of 27 files and returns `sha256` of the lines `"<name>:" .. sha256(bytes)`. The list: `source/simple_map.lua`, `zone_field.lua`, `schemas.lua`, `canonical.lua`, `deterministic.lua`, `index128.lua`, `simple_map.lua`, `height.lua`, `terrain_field.lua`, `terrain_data.lua`, `water_layout.lua`, `road_layout.lua`, `water_authored.lua`, `zones.lua`, `r5.lua`, `r6.lua`, `r7_runtime.lua`, `world_assembly.lua`, `preparation_source.lua`, `preparation_identity.lua`, `capital_planner.lua`, `r7_capitals.lua`, `r7_capital_blueprint.lua`, `capital_protection.lua`, `../wp13/city_edge.lua`, `../wp13/plot_approach.lua`, `../../../CORE/grug_core/preparation_plan.lua`. Bytes, not behaviour: a comment or whitespace edit changes the digest. A file missing from disk raises "Preparation authority source unavailable" at load for every world (so deleting or renaming a listed file also needs a list edit). Of this package, `map_adapter.lua` and `counting_allocator.lua` are not listed.
  - *How it becomes the identity.* `r7_runtime.lua:548-554` builds the string `full_seed .. ":" .. manifest.values.source_projection_sha256 .. ":" .. <file digest> .. ":" .. layouts_digest()` (`layouts_digest`, `:334-343`, hashes the water, road, capital-layout and placement texts), and `preparation_source.lua:66-71` hashes it together with the reach, the below/above envelope and every fitted settlement/anchor box into `source.identity = "grug_surface_v1:" .. sha256(...)`. So the identity also changes when the generated layouts or any fitted box change, not only on file edits.
  - *What happens on a mismatch.* `mods/CORE/grug_core/starts_preload.lua:74-121`, run from `register_on_mods_loaded` (`:171`): only when the world's persisted preparation mode is `full`, the identity is computed; on the first start the plan is created and `state.authority` is stored (`:92-96`); on every later start (`state.total` set — the plan stays persisted after the preparation finishes, `preparation_plan.lua:235-244` never clears it) `assert(state.authority == source.identity, "Surface preparation authority changed; restore the original game and mapgen settings")` (`:110-112`) aborts mod loading, so the server does not start. There is no acceptance or migration path; the only way out is a map reset (`grug_reset_world`), whose clear handler keeps only `{mode = ...}` (`:7-13`) so the next start builds a new plan and stores the new identity. `CHANGELOG.md:1078-1082` already announced one such break to server admins.
  - *Who is affected.* Only worlds whose persisted mode is `full`: the mode comes from `grug_prepare_full_world` (`settingtypes.txt:75`, default `false`) at world creation and is immutable afterwards (`starts_preload.lua:14-26`). Worlds in the default `starts` mode never compute or compare the identity (`source` stays nil), and per the changelog the hosting platform uses that mode. So for most worlds a byte-identical-output edit to these files is compatible; it is a hard upgrade break only for the opt-in `full` worlds, which must ship together with a map reset or be called out in the changelog. The finder's "map reset class" labels above have been narrowed to "`full`-mode map reset" accordingly.
  - Separately, `layout_cache.lua` digests the whole mapgen mod tree through the same routine (`preparation_identity.lua:4-7`), so any edit to `grug_mapgen` rebuilds the world-folder layout cache once (harmless).
