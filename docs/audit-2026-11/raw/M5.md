# M5 — Mapgen: assembly, caches, protection, mod top level

- Finder model: claude-opus-5-5
- Files read in full: 22 of 24; skimmed: `wp40/r20_poi_catalog.lua` (data rows), `wp40/r31_pvp_catalog.lua` (read, small; rows generated); not reached: none. Read beyond the package for the seams: `wp40/r7_loader.lua`, `wp40/r7_mapgen.lua`, parts of `wp40/r7_runtime.lua`, `grug_core/starts_preload.lua`, `grug_core/protection.lua`, `grug_core/water_guard.lua`, `grug_core/zone_authority.lua` (world feature part), `grug_core/migrations.lua` (0.69.0), `tools/check_upgrade.py` (town check only).
- Summary: The package is in good shape as code: the layout cache is careful (every failure path rebuilds, the key covers every input of the four layout texts), `world_protection.lua` is correct and cheap, and the rewrite/hand-over layers (`camp_rewrite.lua`, `wp43_handoff.lua`) are live, not leftovers. The most valuable item is a seam outside the files but owned by this package's identity routine: the full-preparation authority digests the raw bytes of 27 source files, and `starts_preload.lua` asserts on a mismatch at every boot even after the preparation has finished, so a comment-only edit in a "compatible" release puts every full-mode world into a crash loop; no tool checks it (M5-01). Second, the terrain-damage guard (`world_alterable`) and the water guard ignore the world-protection layer, so player water flows onto roads and into POI/village/camp cores outside hard-protected territory (M5-02). The rest is small: stale docs, one game-unreached file (`wp13/troll_palette.lua`), unread schema strings, a global JIT tweak that reaches every mod.

## Findings

### M5-01 | High | persist | Full-preparation authority stops every full-mode world on any byte edit of 27 files, also after the preparation is done

- **Where:** `mods/MAPGEN/grug_mapgen/wp40/preparation_identity.lua:251-272`; `mods/MAPGEN/grug_mapgen/wp40/r7_runtime.lua:548-553`; `mods/MAPGEN/grug_mapgen/wp40/preparation_source.lua:63-71`; `mods/CORE/grug_core/starts_preload.lua:79-87,97-112,172`
- **What:** The preparation identity is a SHA-256 over the whole-file bytes (comments included) of 27 files, combined with the seed, the WP43 material projection digest and the four layout texts, then hashed with the template reach and every settlement/anchor box. `initialize()` (on_mods_loaded) asserts `state.authority == source.identity` for every full-mode world that has a plan, whether or not the plan is finished. An error in an on_mods_loaded callback aborts server start, so the world fails to boot on every start until the old files return. A comment-only or output-identical edit to any of the 27 files is therefore an upgrade-breaking change for full-mode worlds, and nothing catches it: `tools/check_upgrade.py` compares only what the towns build.
- **Evidence:** `starts_preload.lua:110-112` `assert(state.authority == source.identity, "Surface preparation authority changed; restore the original game and mapgen settings")` sits in the `else` branch of `if not state.total` (`:92`), with no `ready()` test (`ready` is `:43`). Engine: `runCallbacksRaw` turns a Lua error into `scriptError` (`reference_projects/luanti/src/script/cpp_api/s_base.cpp:386-388`), raised from `ScriptApiServer::on_mods_loaded` (`s_server.cpp:141-150`). The contract knows it (`docs/technical/upgrade-contract.md:604-606`: "the files `preparation_identity.lua` lists stay byte-identical, or a world in `full` preparation mode stops at its next start"), but `tools/check_upgrade.py:299-312` runs only `validate`, the registry, the migrate steps and `town_errors`. Since 0.41.0, `git log --since=2026-10-07` shows 15 commits touching just `r7_runtime.lua`, `road_layout.lua` and `capital_planner.lua`. A map reset is safe: it keeps only the mode (`starts_preload.lua:7-13`), so the next start makes a fresh plan with the new authority.
- **Proposal:** In `starts_preload.lua` `initialize()`: (a) skip the authority comparison when the stored plan is ready (`state.cursor == state.total`): a ready plan never scans again (the globalstep returns at `:187`), so the authority steers nothing; (b) for an unfinished plan, log a warning and start a new plan (keep `mode`) instead of asserting. Already generated chunks come back as `EMERGE_FROM_DISK`, which `dispatch` counts as success (`:149-155`), so the redo is cheap. Also add a byte check of the 27 files against the pushed base to `check_upgrade.py` as long as (b) is not done. What must stay the same: the identity value itself (worlds store it), the plan format and the mode.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Confidence:** high

### M5-02 | Medium | security | Terrain-damage and water guard ignore the road and POI-core protection: player water floods roads and POI, village and camp cores

- **Where:** `mods/CORE/grug_core/protection.lua:39-44,82-85`; `mods/CORE/grug_core/water_guard.lua:25-33,80-89,104-120`; `mods/ITEMS/grug_farming/bucket.lua:10-24`; layer source `mods/MAPGEN/grug_mapgen/wp40/world_protection.lua:283-347`

The terrain-damage guard `grug_core.world_alterable` asks only the territory rule plus the registered alteration guards, and the water guard's `guarded()` asks only `world_alterable`. In contested land (every level 31-60 zone) and in home territory, a player may pour water two nodes beside a road or a core; it then flows onto the road or into the core. That washes away floodable dressing (torches, plants) and leaves the flow there for as long as the placer's source remains. AGENTS.md "Terrain-damage guard" says POIs are never damaged. Vegetation growth already respects the layer (`ground_growth_allowed`, `protection.lua:50-53`); liquids do not.
- **Evidence:** `protection.lua:39-44` (`natural_ground_alterable` is true for `accord_home`, `throng_home`, `contested_land`); `:82-85` (`world_alterable` adds only `world_alteration_guarded`); the only registered alteration guard is the housing arrival cube (`rg register_world_alteration_guard mods/` → `grug_housing/protection.lua:96`); `water_guard.lua:25-26` `if grug_core.world_alterable(pos) then return false end`; `bucket.lua:19-20` checks only the target cell (`core.is_protected(pos)` + `world_alterable(pos)`), and the corridor reaches only 1 node past the road edge (`world_protection.lua:39`).
- **Proposal:** In `water_guard.lua` `guarded(pos)`, treat `grug_core.world_feature_at(pos) ~= nil` as guarded (before the planned-flow exception, which only concerns protected inland water steps). Make `world_alterable` false on a world feature as well, if the user agrees the guard covers roads too (AGENTS.md names POIs; roads are a ruling-15 layer). Keep the revert node as the plain old node there, not the barrier: `water_guard_revert_node` already gives the barrier only on fixed territory. Cost: one `kind_at` per guarded liquid event, an index lookup plus a few records (`world_protection.lua:283-347`).
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Confidence:** medium (mechanism proven from the code; the actual damage depends on which POI dressing is floodable)

  2. `grug_gathering/catalog.lua`;
  3. `r7_native.lua`;
  4. `layout_cache.lua` and `preparation_identity.lua`;

  **Mapgen threads:** only `wp40/r7_mapgen.lua` is registered. It loads `jit_tuning.lua`, `grug_core/severe.lua`, `r7_native.lua`, `grug_gathering/catalog.lua`, `r7_runtime.lua` (from the IPC texts), `air_chunks.lua`, `degrade.lua`, `guild_rooms.lua` and `guild_room_writer.lua`, with one `on_generated` callback. `num_emerge_threads` must be 1 (`r7_runtime.lua:109-111`).

  The only `on_generated` callbacks in the game are `r7_mapgen.lua:126` (emerge), `init.lua:46` (wayposts, main) and `grug_core/severe.lua:70` (main relay).

  Unreached files: only `wp13/troll_palette.lua` (185 lines; M5-04). No earlier generation of the generator survives as a file. They survive as code paths instead: the offline evidence constructors in `r7_runtime.lua:432-437,563-571` (`evidence_mode`) and the R5 manifest literals (M5-05).
- **Preparation authority, precisely** (for every lane that edits mapgen files). Identity = `full_seed .. ":" .. manifest.values.source_projection_sha256 .. ":" .. preparation_identity(wp40) .. ":" .. layouts_digest()` (`r7_runtime.lua:548-553`). Here:
  - `source_projection_sha256` is the WP43 material projection, i.e. the `grug_materials` tiers, resources, processed materials, woods, regions and density (`wp43_handoff.lua:169-182`).
  - `layouts_digest()` hashes the water, road, capital and placement texts (`r7_runtime.lua:334-343`).
  - `preparation_identity(wp40)` hashes the **whole bytes** of exactly these 27 files, relative to `wp40/` (`preparation_identity.lua:252-263`): `source/simple_map.lua`, `zone_field.lua`, `schemas.lua`, `canonical.lua`, `deterministic.lua`, `index128.lua`, `simple_map.lua`, `height.lua`, `terrain_field.lua`, `terrain_data.lua`, `water_layout.lua`, `road_layout.lua`, `water_authored.lua`, `zones.lua`, `r5.lua`, `r6.lua`, `r7_runtime.lua`, `world_assembly.lua`, `preparation_source.lua`, `preparation_identity.lua`, `capital_planner.lua`, `r7_capitals.lua`, `r7_capital_blueprint.lua`, `capital_protection.lua`, `../wp13/city_edge.lua`, `../wp13/plot_approach.lua`, `../../../CORE/grug_core/preparation_plan.lua`.

  `preparation_source.lua:66-71` then hashes that string with the tree-template reach (`tostring` of the max rotation extents) and every settlement blueprint box and anchor row into `grug_surface_v1:<sha>`. On a mismatch, `starts_preload.lua:110-112` asserts in on_mods_loaded and the server does not start (engine: `s_base.cpp:386-388`). This happens for every world in `full` mode with a plan, **finished or not**; starts-mode worlds are not affected (`source` is nil, `:80-87`).

  Consequences:
  - A comment-only edit to any of the 27 files is an upgrade-breaking change for full-mode worlds.
  - So is an output-identical refactor of them.
  - So is any change to a `grug_materials` resource or tier field that enters the projection.
  - So is a change to a settlement blueprint's bounds.

  A byte-identical-output edit to any *other* mapgen file is harmless here. It rebuilds the world-folder caches once, which is also harmless. A map reset clears the plan (`starts_preload.lua:7-13`), so map-reset releases are safe. Fix proposal in M5-01.
- **World-folder layout cache:**
  - **Key:** `format | seed | source | settings | interpreter`. `source` is the preparation-identity routine over every `.lua/.tpl/.layout/.roster` under `grug_mapgen` (byte-sorted; `layout_cache.lua:48-73`). `settings` is `mg_name, water_level, mapgen_limit, chunksize, mg_flags, mgv7_spflags` (`r7_loader.lua:61-65`).
  - **Inputs:** The layouts read nothing outside the tree (`world_assembly.lua` takes only `wp40_directory` and `raw_sha256`), so every input is in the key.
