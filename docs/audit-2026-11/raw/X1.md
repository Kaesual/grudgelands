# X1 — Ambience, text, sounds, perf monitor, configuration consistency

- Finder model: claude-opus-5-5
- Files read in full: 10 of 10; skimmed: none; not reached: none (consistency checks: settings fully, dependency sweep fully by a static `<global>.` sweep, locales by count and sample for 5 mods, globals by a top-level assignment sweep)
- Summary: The four mods are in good shape. grug_ambience keeps its per-player work within the documented slot scheme. grug_text builds glyph names only from the charmap, so player text cannot inject texture modifiers. grug_perf matches the v1 contract in platform.md field for field and does constant work per step. No High or Medium defects were found. The most useful items: grug_sounds turns a call with a removed ObjectRef into an unpositioned sound for every player (X1-01); the two atmosphere switches quietly turn off the ambience's zone beds (X1-02); and several settings are read but never declared (X1-03). The dependency sweep found no load-order luck: every one of the 29 undeclared cross-mod uses is inside a function body or `register_on_mods_loaded`. The mod map's list of these couplings is out of date (X1-06). No grug mod defines a global beyond the rule and its two documented exceptions. No grug mod has a locale or a translator; only vendored mods carry `.tr` files, some with stale entries.

## Findings

### X1-01 | Low | edge | grug_sounds.play sends a sound for a removed ObjectRef to every player, unpositioned

- **Where:** `mods/CORE/grug_sounds/init.lua:326-352`
- **What:** `target_key` treats anything with `get_pos` as an object. For a removed entity, or a stale ref of a player who left, `is_player()` is false, so the call sets `params.object = target`. The engine then ignores the object, leaves the sound `Local`, and sends it to every connected client at full gain with no distance check. The guard costs one call. Callers that can pass a target removed earlier in the same step include `grug_projectiles/init.lua:371` (`hit.target`) and `grug_abilities/scout.lua:149`. mobs_redo can remove a mob at once on death (`mods/ENTITIES/mobs/api.lua:1061-1086` `remove_mob`).
- **Evidence:** engine `src/script/common/c_content.cpp:1349-1357` applies `object` only when `ObjectRef::getobject` returns a live SAO, and `src/script/lua_api/l_object.cpp:38-44` returns nullptr for a gone object, so the type stays `Local`. In `src/server.cpp:2336-2370`, `pos_exists` is false for `Local`, so the check passes and every client is added, with no `max_hear_distance` test. `is_player` is false for a gone object (`l_object.cpp:1129-1135`).
- **Proposal:** in `play` (and `stop`), return false when `object and not target:is_valid()` (5.18 has `is_valid`, `l_object.cpp:3068`). Live targets behave exactly as now.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Confidence:** medium. The engine path is certain. How often a caller really passes a removed ref was not traced at runtime.

### X1-02 | Low | docs | The atmosphere switches also turn off the ambience's Battlegrounds, dragon-island and ocean beds

- **Where:** `mods/CORE/grug_ambience/init.lua:686-687`, `rules.lua:75-85`; `mods/CORE/grug_core/atmosphere_zones.lua:586-591`, `atmosphere.lua:271-273`; `settingtypes.txt:19,29`
- **What:** The ambience takes its zone overrides from `grug_core.get_atmosphere(name)`, the mood the atmosphere driver applied. With `grug_atmosphere_enabled = false` or `grug_atmosphere_zones = false` the driver never runs, so no mood is set. The Battlegrounds and dragon islands then play their biome group's bed instead of their own, and the dragon-island thunder call (`data.lua:246-247`, keyed on `dragon_island`) never plays. The open ocean survives through the ownerless-column rule (`data.lua:101-104`). The settingtypes texts describe both switches as lighting and sky only. sound.md and the module guides do not mention the coupling (rg "atmosphere.*off" over `docs/design/sound.md` and `docs/technical/modules/` finds nothing).
- **Evidence:** `atmosphere_zones.lua:586` (`if not (grug_core.atmosphere_enabled and zones_enabled) then return end`, before the driver registers anything); `atmosphere.lua:271` (`get_atmosphere` returns `applied[name]`, which stays nil); `init.lua:687` (`if not MOODS[mood] then mood = nil end`); `rules.lua:77` (overrides apply only from the mood).
- **Proposal:** decide which side is right. Either the ambience takes the override from the zone itself (the zone id is already in `column.zone_id` from `depth_below_surface`), or the two settingtypes texts add "also drives the zone ambience beds". The beds must stay the same with the switches on.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Confidence:** high

### X1-04 | Low | dead | grug_sounds' join callback for the formspec prepend is always overwritten

- **Where:** `mods/CORE/grug_sounds/init.lua:384-390` and its header comment `:28-31`
- **What:** grug_sounds appends `CLICK_STYLE` to the prepend in its join callback. grug_core depends on grug_sounds, so it loads later, and its join callback runs afterwards. That callback replaces the whole prepend with `grug_core.ui.prepend(false)`, which already ends in `grug_sounds.CLICK_STYLE`. The grug_sounds callback's result is therefore never seen. Its comment ("`default` sets the prepend on join ... extends that prepend") describes the state before grug_core took over.
- **Evidence:** `mods/CORE/grug_core/init.lua:7-12` (its comment says so); `mods/CORE/grug_core/ui.lua:76-80`; `mods/CORE/grug_core/mod.conf` (`depends = grug_sounds`). Join callbacks run in registration order (builtin `register_on_joinplayer` appends to `core.registered_on_joinplayers`).
- **Proposal:** delete `init.lua:384-390` and adjust the header comment so it names `grug_core.ui.prepend` as the carrier. The prepend string players get stays byte-identical.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Confidence:** high

## Good to know

- **Sound handles on leave:** grug_ambience drops a leaving player's state without stopping its loops. That is correct: the engine removes the departing peer from every playing sound in `Server::DeleteClient` (`src/server.cpp:3160-3170`). The music push callback is guarded by `states[player_name]` (`init.lua:614-615`).
- grug_ambience's layer rules never fade a kept handle to 0. A sound at level 0 sits at `LEVEL_FLOOR` until it is stopped (`rules.lua:288-299`), so the engine's erase on fade-to-0 (`server.cpp:2424-2442`) cannot strand a handle the code still uses.
- grug_text cannot be texture-injected: player text becomes code points, and glyph names come only from the `[%w_]+` charmap (`layout.lua:146,164`). Its entities are `static_save = false` and live while their block is loaded (`serverenvironment.cpp:1682-1685`), as its header says.
- **grug_perf against the contract:** the fields, their order, types, optional fields (rtt and jitter absent with no samples), rounding, the 4096-byte limit, spike spacing and the per-step cost all match platform.md "Performance log lines". The profile save matches the engine's `/profiler` func and file naming (`builtin/profiler/init.lua:31-45`, `reporter.lua:225-268`).
- **One-global rule:** no extra global found. Top-level assignments in grug mods are the mod tables, `grug_items` (grug_quality) and `grug_zones` (rawset, grug_core). The other 26 top-level assignments (`tick`, `hud_update`, `flush`, ...) are forward-declared locals. Assignments inside functions are left to `tools/check_lua.sh`'s SETGLOBAL listing, which this audit could not run.
- grug_mobs' three `mobs.mob_class.on_deactivate` replacements (`init.lua:24`, `start_npcs.lua:1173`, `liveness.lua:158`) each chain to the previous one.
- **Locales:** none of the 54 grug mods has a `locale/` folder or calls `core.get_translator`, so all game text is English (ROADMAP.md:256 plans localisation). Only vendored mods translate: 11 BASE mods with about 22 languages each, and the mobs fork with 14. A non-English client therefore sees a mix: vendored item names translated, everything grug untranslated, and patched default strings partly untranslated.
- `minetest.conf`: every entry has a reader, either the engine (mapgen tuple, liquid fluidity, the client render switches), the mobs fork (`mob_active_limit`, `mob_nospawn_range`, `remove_far_mobs`, `mobs_can_hear`), or grug code (`grug_prepare_full_world`, `grug_map_quality`, `num_emerge_threads` through `r7_runtime.lua:110`). `game.conf` holds only engine keys plus `version`, which help.lua reads.
