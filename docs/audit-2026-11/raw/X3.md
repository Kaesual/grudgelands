# X3 — Dead code and dead files across mods

- Finder model: claude-opus-5-5
- Files read in full: 0 of 628 own Lua files (cross-mod sweep by search; about 45 sites read in part to confirm each claim); skimmed: `mods/BASE/*`, `mods/ENTITIES/mobs` (only as whole mods and media); not reached: per-item reachability of registered nodes/craftitems/entities registered through variables (only literal names and debug/test patterns were checked), media families covered by a `"prefix" ..` literal were checked for 14 of 46 families (see Good to know)
- Summary: The game is in good shape for dead files: a load graph built from every `init.lua` (dofile/loadfile, `register_mapgen_script`, the `composition()` and `<key>_districts.lua` / `talent_graph_<class>.lua` name builders) reaches 627 of 628 own Lua files; the one left over (`wp13/troll_palette.lua`) is documented as tools-only. Sounds, models, music, building templates and settings are all referenced; there is no `minetest.` in our code, no commented-out code and no live TODO. The valuable items are code-level: the R7/R6 evidence and capture construction modes plus their fixture seams in the hottest mapgen files have no caller anywhere (not even `tools/`), 12 public functions on mod globals have no caller anywhere and 27 more live only for fixtures, about 35 exported constants and aliases are never read, and one data table (`grug_cooking.REFINEMENTS`) is read by nothing. Unused media is small: six navigation icons (text-only navigation since Round 67) and a few single frames. Two dead dev settings from audit 2026-10 (X-11) are still in place.
