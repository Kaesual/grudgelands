# C3 — Classes, skills, XP, PvP, factions

- Finder model: claude-opus-5-5
- Files read in full: 23 of 27; skimmed: `grug_classes/talent_graph_mage.lua`, `talent_graph_priest.lua`, `talent_graph_warrior.lua`, `talent_graph_scout.lua` (data tables: headers and vocabularies read, node rows skimmed; every class effect key was checked for a consumer, and the load-time `graph.audit` checks shape, gates, rank sums and reachability); not reached: none
- Summary: The package is in good shape on the rules the special focus names. The XP curve, kill and gathering formulas and their examples match progression.md and combat_stats.md exactly. The PvP flag timers are absolute `os.time()` values that are saved, so a relog does not reset the flag (unlike the C2 cooldown reset). A logout in PvP combat is a death, and stored talent strings are validated on every read (unknown ids dropped, ranks clamped, budget refunded). Character creation cannot be redone or bypassed by a player: a complete character never gets a creation session, and `/faction`, `/race` changes need `server`. The most valuable items are: (1) the 1 s PvP location pass handles every connected player in one step, with two zone classifications per player that grug_map's phased sampler repeats; (2) the identity accessors (`get_level`, `get_class`, `get_faction`, `get_race`) read player meta on every call, and `get_level` adds a linear scan of up to 59 steps, all on per-hit and per-ray paths; (3) the skill-item guard for detached inventories runs only at join and on a catalog render, so a furnace workspace opened later accepts a skill stack. The rest is docs drift and small dead code.

## Findings

### C3-01 | Medium | perf | The 1 s PvP location pass samples every connected player in one step

- **Where:** `mods/PLAYER/grug_pvp/init.lua:285-312` (`location_tick` and its globalstep), `:262-275` (`sample`), `:248-251` (`zone_answers`), `:99-113` (`notify`); `mods/MAPGEN/grug_mapgen/wp40/zones.lua:1176-1180, 1205-1215`; compare `mods/PLAYER/grug_map/location.lua:221, 247-251`
- **What:** Once a second the globalstep walks `core.get_connected_players()` and, for each living player outside creation, calls `zones.pvp_rule_at(pos)` and, on peaceful ground, `zones.faction_at(pos)`. That is two `classification_values` lookups. It also calls `get_faction` (a meta read) and `notify`, which builds a fresh `R.state` table per player. All of this runs in the same server step, which breaks AGENTS.md "No pass handles every player or zone in one step". `grug_map/location.lua` already samples the same position per player on a staggered phase (`JOIN_PHASE`, `next_sample`) and asks `grug_pvp.territory_at` for the same two zone answers, so the territory is classified twice per player per second. Each sample is also wrapped in two `core.get_us_time()` calls that feed `grug_pvp.tick_stats`. Only probes under `tools/` read that table.
- **Evidence:** `init.lua:290-301` loops over all players in one pass. `:294-297` writes `tick_stats`. `rg -n tick_stats mods tools` finds only `tools/r31_pvp/grug_probe_r31_pvp/init.lua:444` and `tools/r37_po/grug_probe_r37_po/init.lua:636` outside this file. `grug_map/location.lua:122` calls `pvp.territory_at(pos, ...)`, the same rule.
- **Proposal:** Give each record a phase, as grug_map does: `next_sample = now + (join index * phase) % 1`. Then run the globalstep at about 0.1 s and handle only the records that are due. Keep the 1 s cadence per player and the "sample, then notify" order, so flag behaviour stays identical. Drop the `get_us_time` pair and `tick_stats` from the production path, or put it behind a debug setting, and update the two probes. Optionally, let grug_map reuse grug_pvp's last zone answer for the territory line instead of classifying again (same rule, `R.territory`).
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Measure:** unmeasured. Use 100 stand-in players spread over contested and peaceful ground (any seed). Compare the longest single server step attributable to `grug_pvp` (profiler mod section) and the total per second, before and after.
- **Confidence:** high

### C3-02 | Medium | perf | Level, class, faction and race are read from player meta on every call; `get_level` also scans the level table linearly

- **Where:** `mods/PLAYER/grug_xp/init.lua:104-110, 130-140` (`level_from_xp`, `get_xp`, `get_level`, installed as `grug_core.get_player_level`); `mods/PLAYER/grug_classes/init.lua:41-49, 86-98`; `mods/PLAYER/grug_factions/init.lua:53-61, 192-215`; `mods/PLAYER/grug_classes/stats.lua:15-24, 143-169`
- **What:** `get_level` does `get_meta():get_int` and then a `while` loop over `LEVEL_START`, which takes 59 iterations at level 60. `get_class` and `get_faction` each do a meta `get_string`. `get_race` reads its own key plus `get_faction`. These accessors sit on the per-hit and per-ray paths. `get_crit_chance_raw` and `get_dodge_chance_raw` each call `get_attributes` (a `get_level` and a `get_class_def`). `grug_factions.hostile` and `same_faction` read two factions per check (crosshair ray, `can_harm`, mob targeting `grug_mobs/init.lua:984, 1045`, nametags). `scale_player_damage` reads the level per hit. The values change only at a few known writers: XP only through `grug_xp.set_xp`, class only at `set_class` (no class change exists, ruling 20), faction only at `set_faction`, race only at `set_race`.
- **Evidence:** `rg '"grug_xp:xp"|grug_xp:xp' mods` finds the key only in grug_xp, so `set_xp` is the sole writer. `set_class`, `set_race` and `set_faction` are the only writers of their keys (`init.lua:77`, `:114`, `grug_factions/init.lua:231`). Call counts: `rg -c "grug_xp.get_level|get_player_level" mods` gives 7 sites in `grug_core/combat.lua` alone. C2-02 counted about 2,200 `is_unlocked` → `get_class` meta reads per second at 100 idle players.
- **Proposal:** Keep a per-name runtime cache in each owner: `level` (set at join and in `set_xp`), `class`, `faction` and `race` (filled lazily, overwritten by the setter, cleared on leave). The accessors keep their signatures and their registry validation of the cached id. As a smaller step on its own, replace `level_from_xp`'s linear walk with a binary search, or a lookup on the cached level. The stored meta stays the authority, and the `grug_xp:level` key for the website is unchanged.
- **Effort:** M · **Risk:** low · **Upgrade class (guess):** compatible
- **Measure:** unmeasured. Use 100 stand-in level-60 players fighting mobs and 20 player pairs in PvP (any seed), and count `get_meta` calls per second (a wrapper probe) and the `grug_abilities` and `grug_core.combat` profiler sections, before and after.
- **Confidence:** high (that the reads happen); medium (how much it weighs; unmeasured)

### C3-03 | Low | edge | The skill-item guard for detached inventories runs only at join and on a catalog render; the per-join node walk is redundant

- **Where:** `mods/PLAYER/grug_skills/bound_items.lua:116-140`, `page.lua:123`; compare `mods/PLAYER/grug_housing/soulbound.lua:89-96`; workspace `mods/PLAYER/grug_jobs/workspaces.lua:224-231, 266`
- **What:** `wrap_detached` adds the "no bound stack" `allow_put` only to detached inventories that exist when `guard_detached` runs. It runs on any player's join and on every Talents & Skills render. A furnace workspace creates a fresh detached inventory each time it opens (`grug_workspace_<name>_<seq>`), and its `allow_put` accepts any stack in the input list. A workspace opened after the latest join or catalog render is therefore unguarded, and a skill stack dragged from the hotbar lands in it and is saved into the node's meta. The player-side handler covers only `move` and `put`, not `take` (`bound_items.lua:71-94`). The harm is small: it is a junk copy, the catalog is an infinite source, and the item is useless to others. But it breaks the documented rule "external inventories ... refuse bound stacks" (combat-classes.md:113). grug_housing's soulbound guard solves the same problem by wrapping `core.create_detached_inventory` itself, so every later inventory is wrapped at creation. Separately, `register_on_joinplayer(guard_destinations)` walks every registered node on each join. Nodes cannot be registered after load, so after `on_mods_loaded` that walk only re-checks `_grug_bound_guard`.
- **Evidence:** `bound_items.lua:127-140`. `trash.lua:96-104` documents the gap ("grug_skills would wrap the box later (its render and join walks)") and works around it locally. `workspaces.lua:266` creates the inventory per open. Engine behaviour (which callbacks a hotbar-to-detached drag calls) was not checked, because `reference_projects/luanti` is empty.
- **Proposal:** Wrap at creation, as soulbound.lua does: chain a `core.create_detached_inventory` override that applies `wrap_detached` to the callback copy, and keep one `on_mods_loaded` walk for inventories created earlier. Then drop the join hook's node walk and the per-render `guard_detached` call (and trash.lua's workaround). The guard behaviour stays identical, only earlier.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Confidence:** medium

## Backlog notes

- `mods/PLAYER/grug_pvp/init.lua:428`: `damagers[name]` is dropped at leave. A victim who logs out 10-30 s after an enemy hit (flagged, no longer in PvP combat, so no logout death) and dies of something else right after rejoining gets a non-PvP death (durability wear) instead of `R.pvp_death`'s 30 s grace. It is rare and arguably correct.

## Good to know

- XP: `level_xp`, `mob_xp`, `kill_percent`, `kill_xp`, `quest_reward` and `gather_xp` reproduce every number and example in progression.md (240 to level 2, 194,220 cap, L30 player on an L21/L27 mob 17/122, the L10+L1 split 37/22, coal at L1 gives 2). The split, the gray rule and the own-faction zero live in `grug_mobs/init.lua:239-286` and `levels.lua:606-645` (outside this package) and also match. Only `quest` XP is race-scaled, and PvP kills give no XP.
- Level-up refill: `apply_stats(player, new > old)` fills only living characters, and join passes `old_level = nil` (no free heal on relog). A level drop wipes talents for free, as skill_trees §1.4 says.
- Talent state is robust: `graph.parse` drops unknown or foreign ids, clamps ranks, enforces gates and prerequisites, and refunds to `floor(level/2)` deepest-first on every cache fill. A hand-edited string cannot buy an ultimate. Respec takes the money before the reset, and the first respec is free (`grug_classes:respec_used`). Every class vocabulary key has a consumer in grug_abilities (checked with `rg`). Stats are recomputed on equipment change (not pure wear), level change, talents change, status-modifier change and class pick, never per tick.
- Readiness-window ICDs deliberately survive relog and death (talent_windows.lua:12-14). The open windows end at leave. This is the opposite policy from C2-01's cooldowns, which may matter for the CMB-10 ruling.
- PvP gating itself (crosshair ray, `deal_ability_damage` impact re-check, the on_punchplayer swing handler, mounted hitters refused) lives in `grug_core/combat.lua:1193-1265, 1690-1698`, `combat_ray.lua:439` and `grug_abilities/init.lua:2819-2880`, which belong to other packages. This package only supplies `can_harm`/`can_support` and contact. Friendly fire is blocked twice: grug_factions' on_punchplayer and `deal_ability_damage`'s same-faction zero.
- Creation: the draft is session-only. `draft_ready` re-validates faction, race and class at Create, `set_class` runs only for a classless character, and every other path into creation needs `server` (`/faction`, `/race`). An admin `/faction` on a finished character sends it back into the window (its race no longer matches), with its class kept. That is intended self-healing.
- Engine claims (callback modes, the `set_hp` reason table reaching `on_dieplayer`, detached-inventory callback order) were not checked: `reference_projects/luanti` is an empty checkout.
