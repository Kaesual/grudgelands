# MOB2 — grug_mobs spawning and population

- Finder model: claude-opus-5-5
- Files read in full: 14 of 14; skimmed: none (the long rationale comments of rares.lua 333-631 and the LINES table of start_villagers.lua were read but not checked number by number); not reached: none
- Summary: The spawning core is in good shape: spawn rows really do go only through the three merged ABMs (spawn_abms.lua is the only `register_abm` in grug_mobs), the region-map cache follows the world-key rule (key = `grug_mapgen.wp40.world_key` + builder digest, every failure pcall'd into a rebuild), the ambient attempts and the camp/leader pass are sliced, and the start NPC engine has thorough duplicate protection (markers, identity scan, age rule, `_grug_unplaced`). The most valuable items are cost on hot paths that the slicing does not reach: every ABM spawn attempt that passes the policy still pays mobs_redo's 33x33x33 `find_nodes_in_area` for a repellent node the game unregistered, plus a 128-node object scan, before the cheap height and light checks (MOB2-01); and the start NPC heartbeat serves every registered settlement in one step every 5 s (MOB2-02). Region camps count and spawn at a range where their members' blocks can be inactive, so a camp can overfill (MOB2-03). Since every one of the 38 zones has a recipe, the whole palette layer of spawn_policy.lua/spawn_regions.lua, the bandit/mirefolk camp-fire mechanism and most surface rows of start_zone_families.lua and night_families.lua are dead code (MOB2-04, MOB2-05).

## Findings

### MOB2-01 | Medium | perf | Every ABM spawn attempt scans 35,937 nodes for an unregistered repellent and a 128-node object radius before the cheap checks

- **Where:** `mods/ENTITIES/mobs/api.lua:4508-4590` (spawn_action, reached from the merged dispatcher `mods/ENTITIES/grug_mobs/spawn_abms.lua:207-224`); `mods/ITEMS/grug_materials/content_curation.lua:100-108`
- **What:** The row action that every merged spawn ABM calls runs, in this order: `spawn_abm_check` (the grug policy), `count_mobs` (`get_objects_inside_radius(pos, 128)`), the day toggle, then `core.find_nodes_in_area` over a 33x33x33 box for `mobs:mob_repellent`, and only then the height and light limits. `mobs:mob_repellent` is not registered at all (content_curation.lua:100-108, "not registered at all"), so the repellent scan can never find anything. The height test (`pos.y + 1` within the row's range) and the light test are a few comparisons and one `get_node_light`, yet they run after both expensive scans.
- **Evidence:** api.lua:4534 `mobs:spawn_abm_check`, 4539 `count_mobs(pos, name)` (count_mobs, api.lua:4291-4308, `get_objects_inside_radius(pos, aoc_range * 2)`, `aoc_range` = 4 x 16, api.lua:186), 4568-4573 the repellent `find_nodes_in_area`, 4577-4588 height and light. Called from every merged ABM trigger whose roll picks a row hosted on the node (spawn_abms.lua:211-221), i.e. at the full rate of the underground, water and surface rows. Night rows fail the light test (`max_light = 5`, spawn_policy.lua:579-581) only after both scans; underground rows' light filter (`max_light = 7` etc.) likewise.
- **Proposal:** A GRUG PATCH in spawn_action: drop the repellent scan (the node cannot exist; keep a comment naming content_curation.lua), and move the height and light checks (on a copy `{x, y + 1, z}`) ahead of `count_mobs`, keeping `pos.y = pos.y + 1` where it is for the rest. The outcome of every attempt stays identical; only rejected attempts get cheaper. Related (same lane): `mobs:add_mob` runs `count_mobs` even with `ignore_count = true` only for `is_pla` (api.lua:4385), so a region spawn pays a second 128-node scan after density.lua's own 128-node scan (density.lua:111).
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Measure:** unmeasured. Seed 12345, a player standing at a cave mouth and one on open ground at night, 10 min each: count spawn_action calls and total time in it (wrap `mobs.register_spawn_abm`'s action with `core.get_us_time`), before and after. Engine behaviour of `find_nodes_in_area` with an unknown name not checked (the luanti submodule is not checked out); if the engine returns early for an empty filter, the gain is the reorder only.
- **Confidence:** medium

### MOB2-02 | Medium | perf | The settlement NPC heartbeat serves every settlement in one step every 5 s

- **Where:** `mods/ENTITIES/grug_mobs/start_npcs.lua:1897-1915` (heartbeat), `1716-1794` (`serve`), `1035-1087` (`scan_row`), `1101-1140` (`strikeable`)
- **What:** Every 5 s one globalstep step runs `serve` for every row: the 6 starts, 6 capitals, the Round 14 POIs, both fortresses, the war camps and the Round 58 camps. Each `serve` does a `get_objects_inside_radius(anchor, scan_radius)` (for a capital the radius covers its district sockets plus 48, roughly 300 nodes) and then walks every slot: a placed but unseen slot costs a `compare_block_status` (twice with an away record), a pending slot a `get_node_or_nil` and up to 9 more in `standing_cell`. Rows nobody is near still pay the per-slot loop each time (all placed slots read unoccupied, so each asks `compare_block_status`). This is the "no pass handles every player or zone in one step" rule of AGENTS.md "Performance"; spawn_regions.lua already slices the same kind of work (`SR.SLOW_SLICES`).
- **Evidence:** start_npcs.lua:1903-1914 loops `for index = 1, #rows` and calls `serve(row)` for each in the same step ("Every row, every heartbeat"); 1038 the radius scan; 1722-1791 the per-slot loop; 840-852 `scan_radius` grows with every socket's distance from the anchor.
- **Proposal:** Spread the rows over slices of the 5 s period (e.g. 20 slices of 0.25 s, row index modulo slice, like spawn_regions.lua:1281-1339), so each row is still served once per `PLACE_INTERVAL`. Keep `serve_ready_settlements` as is (one-off). Optionally skip the per-slot strike loop when `scan_row` found nothing and the anchor block is not active. Behaviour (one pass per row per 5 s, FREE_STRIKES semantics) stays identical.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Measure:** unmeasured. Seed 12345, 30 stand-in players spread over Highcourt, Nhal Veyr and two starts: max and mean duration of the heartbeat step (core.get_us_time around the loop), before and after; the probe tools/r37_* census can confirm placements unchanged.
- **Confidence:** high

### MOB2-03 | Medium | edge | Region camps count and spawn while their members' blocks can be inactive, so a camp overfills (and refills slowly after unload culling)

- **Where:** `mods/ENTITIES/grug_mobs/camps.lua:942-1050` (`REGION_CAMP_RANGE`, `count_region_members`, `region_camp_tick`); compare `mods/ENTITIES/grug_mobs/spawn_regions.lua:1116-1121` (`SR.LEADER_RANGE`)
- **What:** A region camp is counted and refilled whenever a player is within 80 nodes of its centre horizontally (camps.lua:942, 1010), and its members are counted within 88 nodes of the centre (958-968). Members stand up to 40 nodes from the centre (978) and roam a further 32. With the default `active_block_range` of 4 blocks, a player 70-80 nodes from the centre leaves the far half of the camp, sometimes the centre itself, inactive; `get_objects_inside_radius` does not see those members (the file's own note, 92-95), the tick books them as missing (1025-1029) and serves one refill per 30-60 s while the player stays there. `mobs:add_mob` accepts a position up to 128 nodes from a player (api.lua:4385-4390, `count_mobs` radius 128), and region mobs are static-save (api.lua:3691-3692), so a member spawned into an inactive block is stored, not dropped. When the player then walks in, the camp holds more than `slots` members; nothing removes the surplus. The leader code avoids exactly this with `SR.LEADER_RANGE = (active_block_range - 1) * 16` (spawn_regions.lua:1116-1121). The reverse case: members culled on block unload (remove_far, minetest.conf:55-73: a linear cull chance from 48 to 128 nodes) are only booked when a later look sees them missing, with `next_refill = now + interval` (1026-1028), so a camp a player returns to refills one member per 30-60 s; the `fill` catch-up exists only for the first look after a restart (1017-1023).
- **Evidence:** camps.lua:942 `REGION_CAMP_RANGE = PLAYER_RANGE` (80); 960 radius `camp_radius() + 48`; 1010-1033 booking; 1035-1043 drain; camps.lua:936-939 calls the blind spot "briefly one too many", which assumes the count radius stays inside the active area.
- **Proposal:** Count and refill a camp only while its centre's block is active and a player is within `SR.LEADER_RANGE` (or `compare_block_status(center, "active")`, as start_npcs.lua:1101-1103 does). For the return case, keep a `last_seen` per camp in `region_camps` and, when a look after an absence books new deficits, start the drain at `last_seen + interval` (the fire camps' catch-up semantics, camps.lua:62-75), so absence earns refills as it does for guard posts. Slot counts, respawn ranges and the first-look fill stay as they are.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Confidence:** medium (engine active-block shape not checked: submodule not checked out)

## Good to know

- AGENTS.md "spawn rows only through the three merged spawn ABMs" holds: `rg register_abm mods/ENTITIES/grug_mobs` → only spawn_abms.lua:199; no row uses mobs_redo's `map_load` LBM. Groups: underground, water (Kraken, sharks, Tide Goby, Reed Angelfish; y -30..600, interval 30), surface (the recipes' critters and the Rift Spawn).
- The region-map cache follows the world-key rule: `cache_key` (spawn_regions.lua:1362-1384) = `world_key` (seed, mapgen tree digest, settings, interpreter) + digest of `BUILDER_FILES`; every input the build reads outside grug_mobs is under grug_mapgen (covered by the tree digest) or `grug_core/zone_authority.lua` (in the list). Load, decode, rehydrate and store are all pcall'd into a rebuild.
- density.lua (another package) does `get_objects_inside_radius(pos, 128)` per region attempt that reaches the density gate (density.lua:111), and `add_mob` does a second 128-node scan (MOB2-01); these are the two biggest per-attempt costs of the ambient spawner, not the region lookup (`region_at` is a string byte read).
- Start NPC duplication after restarts is well defended (markers in mod storage, `_grug_unplaced` first-snapshot guard, per-socket identity scan, age rule in `start_npc_claim`, `FREE_STRIKES` with `compare_block_status`); I found no path that duplicates. The map reset clears every grug_mobs storage key but the liveness generations (map_reset.lua).
- Region camp state (`region_camps`) and `live_leaders` are memory-only by design; leaders are `static_save = false`, so no leader survives a restart or an unload.
- The engine submodule `reference_projects/luanti` is empty in this checkout; engine claims above that rest on it are marked.
- spawn_regions_core.lua is clean on determinism otherwise: every `pairs` over string keys is sorted before use (lines 955, 1117, 2277), ties broken by grid order.
