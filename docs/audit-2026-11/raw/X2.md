# X2 — Duplication across mods

- Finder model: claude-opus-5-5
- Files read in full: n/a (cross-cutting search package without a file list; every `grug_*` mod under `mods/` was searched, and each cluster's copies were read at the cited ranges); skimmed: the per-capital mapgen files `mods/MAPGEN/grug_mapgen/wp13/*.lua` and the wp40 validators (at a glance, as the brief asks), the per-species mob files in `mods/ENTITIES/grug_mobs` (a line-frequency comparison only); not reached: a pairwise comparison of the wp40 mapgen modules beyond their small validator helpers
- Summary: Most duplication is small local helpers. The biggest single helper cluster is a 1-line `esc()` in 28 files. The valuable clusters are wrappers that carry rules, and they have drifted. Bound-item inventory guards exist twice (soulbound in grug_housing, skills in grug_skills), and only one of them covers detached inventories created later. The "is this player still allowed to use this NPC's window" check is written six times with different checks for HP, faction, socket and stale entities. grug_clans copies grug_parties' invitation and roster machinery. Five mods rebuild "the lists a player owns" next to `grug_inventory.carried_lists`/`consume_lists`. The six capital plot modules of mapgen wp13 are about 60 % shared (~2,900 lines). No duplicated copy was found that is a player-visible bug on the happy path today; the drift findings are latent or affect rare paths. grug_core already owns most of the targets (`ui`, `item_name`, `mono_time`, `get_player_level`, `settlement_sockets`), so most of the work is replacing copies with calls to it, not building new modules.

## Findings

### X2-01 | Medium | dup | Two bound-item inventory guards (soulbound, skills) with drifted coverage

- **Where:** `mods/PLAYER/grug_housing/soulbound.lua:17-103`; `mods/PLAYER/grug_skills/bound_items.lua:23-29,71-139`; per-render call `mods/PLAYER/grug_skills/page.lua:123`; `mods/PLAYER/grug_inventory/trash.lua:103`
- **What:** Both files guard an item group from leaving the player's carried lists through the same three seams. Each has its own `register_allow_player_inventory_action`, its own `wrap_node` over every registered node (`allow_metadata_inventory_put/move`) and its own `wrap_detached`. The soulbound file says it "follows grug_skills/bound_items.lua". They have drifted. (a) soulbound wraps detached inventories at creation by overriding `core.create_detached_inventory` (`soulbound.lua:91-96`), and it wraps both `allow_put` and `allow_move`. The skills guard wraps only `allow_put` (`bound_items.lua:116-125`), and only for detached inventories that already exist when `grug_skills.guard_detached()` runs. So it re-walks `core.detached_inventories` on every Skills render (`page.lua:123`) and on every join (`bound_items.lua:136-139`). (b) The carried-list rule is spelled three ways: soulbound by string pattern (`soulbound.lua:27-30`: `^grug_bag%d_content$`, `"grug_hotbar_store"`), skills through `grug_inventory.content_list(i)` (`bound_items.lua:23-29`), and grug_inventory itself through `carried_lists`.
- **Evidence:** `soulbound.lua:43-66` and `bound_items.lua:96-114` are line-for-line the same `override_item` wrapper with different flags (`_grug_soulbound_guard` / `_grug_bound_guard`). As a result every node inventory callback carries two extra closure layers. `bound_items.lua:137-139`: `core.register_on_joinplayer(function() grug_skills.guard_destinations() end)` walks all of `core.registered_nodes` on each join, and `wrap_node` returns early only through the flag.
- **Proposal:** Give grug_inventory one "bound item" seam, for example `grug_inventory.register_bound_rule(predicate, allowed_target(list, index, stack, player))`. It installs one player-action callback, one node wrap per node at `register_on_mods_loaded`, and the `create_detached_inventory` hook that soulbound already proves out. Housing and skills then register their predicates: soulbound = group `grug_soulbound` with carried lists; skills = hotbar-only, entitlement and catalog swap. The allow/deny decisions must stay identical, including the catalog swap undo (`bound_items.lua:85-86`). This also removes the per-render and per-join walks.
- **Effort:** M · **Risk:** medium (inventory exploit surface; needs the existing soulbound/skills fixtures) · **Upgrade class (guess):** compatible
- **Confidence:** high

### X2-02 | Medium | dup | "May this player still use this NPC's window" written six times with drifted checks
