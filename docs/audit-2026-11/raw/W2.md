## Good to know

- Upgrade class of a byte change in this package: none of the 42 files is in the preparation-authority default list (`mods/MAPGEN/grug_mapgen/wp40/preparation_identity.lua:9-19` lists only `../wp13/city_edge.lua` and `../wp13/plot_approach.lua` from wp13). The world-folder layout cache digests the whole mapgen tree (`wp40/layout_cache.lua:45-71`), so a byte change costs one cache rebuild at the next boot, not a start failure. But the preparation identity also hashes the generated layout texts (`wp40/r7_runtime.lua:334-343`, `:548-553`), and the capital layout depends on each plot's `bounds` and `clear_to` (`wp40/capital_planner.lua:2598`, `wp40/r7_capitals.lua:157`). So: byte-identical output = compatible; any change to a plot's bounds or `clear_to` = new capital layout = a full-preparation world fails its next start, and the class is "map reset". Moving a per-capital table INTO `wp40/r7_capital_blueprint.lua` (which is digested, line 16 of the list) would make even an output-identical refactor fail full-preparation worlds; keep new modules in wp13.
