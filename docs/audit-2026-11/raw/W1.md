## Findings

### W1-01 | Medium | perf | Each capital's roster and all its templates are parsed up to five times per process

- **Where:** `mods/MAPGEN/grug_mapgen/wp13/templates.lua:805-848` (`M.capital`); callers `wp13/highcourt.lua:63-65`, `wp13/highcourt_plot.lua:59-60`, and the district modules that each `dofile` the plot module: `wp13/highcourt_district.lua:23`, `highcourt_district_martial.lua:18`, `highcourt_district_lore.lua:18`, `highcourt_district_homes.lua:18` (same pattern for dur_brannoc, gor_drazhak, nhal_veyr; lethariel and kezamba twice)
- **What:** `templates.lua` has no cache: every `dofile(directory .. "/templates.lua")(directory)` makes a fresh loader, and every `templates.capital(id)` re-reads and re-parses the roster and every `.tpl` it lists. The core module and every `<capital>_plot.lua` instance call `templates.capital(id)`, and each district module `dofile`s its own copy of the plot module, so Highcourt, Dur Brannoc, Gor Drazhak and Nhal Veyr parse their full template set 5 times and Lethariel and Kezamba 2 times per process.
- **Evidence:** `rg -n "templates\.(capital|town)\(" mods/MAPGEN/grug_mapgen/wp13` lists one call in each core and each `_plot.lua`; `rg -n "_plot\.lua\"" wp13` lists 4 district loaders each for highcourt, dur_brannoc, gor_drazhak, nhal_veyr and 1 each for lethariel and kezamba. Template bytes per roster (distinct templates, `wc -c`): highcourt 307,795; nhal_veyr 270,813; dur_brannoc 263,727; lethariel 225,526; gor_drazhak 219,055; kezamba 207,032. With the multiplicity that is about 6.2 MB parsed for 1.5 MB of input. The kits are built once per process per capital (`wp40/world_assembly.lua:90`, `A.capitals.source.kit`), in main and in every emerge environment, so the waste is load time per environment (main start plus each emerge thread), not per chunk. The parser allocates a table per line (`lines_of`, :67-72), a word table per header/legend line and one `sub` per grid cell (:386).
- **Proposal:** Parse each capital once per process: either let `<capital>_districts.lua` load `<capital>_plot.lua` once and hand the instance to its district modules, or give `templates.lua` a memo of parsed templates keyed by path that the callers share (one loader instance passed down from `r7_capital_blueprint.kit`). Parsed templates are read-only after `parse_template` (only `M.part` reads them), so sharing is safe. `capital.used` counts would then accumulate in one object; `tools/building_templates/loader_check.lua:106` reads `made.used` and must be checked against the new sharing. Output stays byte-identical.
- **Effort:** M · **Risk:** low · **Upgrade class (guess):** compatible (no file in the preparation-authority list `wp40/preparation_identity.lua:9-20` changes; the layout cache key changes, so the first start after the update rebuilds the cached layouts once)
- **Measure:** unmeasured. Time `world_assembly` capital kit construction (os.clock around `A.capitals.source.kit(key)` per key) in main on any seed before/after; expect roughly a 4x drop in template parse time.
- **Confidence:** high
