# P3 — Inventory, quests, trinkets, money

- Finder model: claude-opus-5-5
- Files read in full: 23 of 26; skimmed: `mods/PLAYER/grug_quests/validate.lua` (load-time checks only; function list and the key sets read), `mods/PLAYER/grug_inventory/help.lua` (static help text lines 60-270 skimmed, all code read), `mods/PLAYER/grug_quests/npcs.lua` (static NPC rows 1-59 skimmed, code read); not reached: none
- Summary: The package is in good shape on the dangerous paths. Equip, shift-click, bag resize, quiver, inbox, trash, withdraw/deposit and quest turn-in all preflight before they write, and every leftover lands in the inventory, stays in its slot or drops at the player's feet; I found no realistic duplication or loss path, and the allow callbacks keep the OR-combine contract (nil for foreign lists; numbers only for their own lists). The most valuable items are performance: the quest state cache still pulls the full serialized state string (about 17.6 KB at 450 completed quests, PLY-10's measurement) out of player meta on every read, several times a second per player (P3-01); a Scout's every shot and every arrow pickup rebuilds and re-sends the whole Character page (P3-02, the open PLY-11); and `grug_inventory.give`, which now handles every dug node and every pickup, builds about 200 tables and copies every carried list per call (P3-03). The rest is small: unused exports, stale `mod.conf` dependencies, small duplicates and documentation drift in inventory_equipment.md §1 and economy.md §1. Engine source (`reference_projects/luanti`) is not checked out in this checkout, so engine behaviour claims below are marked.

## Findings

### P3-01 | Medium | perf | Quest state cache re-reads the whole serialized state from player meta on every read

- **Where:** `mods/PLAYER/grug_quests/state.lua:18-39` (`load`), callers `:213`, `:227`, `:262-268`, `:276`, `:325-327`, `:381`, `:442-443`, `:467-468`, `:670`, `:701-702`, `:727`
- **What:** `load(player)` calls `player:get_meta():get_string(KEY)` every time, only to compare it with the cached `raw`. The string holds the whole state, including `completed`, which keeps every quest ever turned in. Each call copies that string out of C++ meta into a new Lua string, which Lua 5.1 then interns (allocation, hashing and a full-length compare against the cached string). The decoded table is cached, but the string read happens every time. `save` (`:44-48`) is the only writer of the key in `mods/` (rg `grug_quests:state` finds only `state.lua:2`), and the cache is dropped on leave (`:75-78`). So the re-read never sees a change the cache does not already have.
- **Evidence:** Readers per player and second: the tracker poll every 0.5 s (`hud.lua:255` → `journal_key` → `load`); the use-point pass every second (`use.lua:250` → `Q.use_needs` → `load`); the NPC tag pass for every observed quest giver every second (`npc.lua:428` → `Q.marker_states` → `load`); the minimap's `static_key` (`grug_map/minimap.lua:378`); and the rift boss's `quest_held` for players near the rift (`grug_mobs/rift.lua:434`, once a second). Add one `load` per eligible kill (`credit_kill`, `:670`). The audit of 2026-10 measured 17.6 KB of serialized state at 450 completed quests (PLY-10, `docs/audit-2026-10/code/08-player-systems.md:127`). With 5-15 reads per player per second, 100 players produce several MB/s of short-lived strings.
- **Proposal:** Trust the cache. `load` reads meta only when `cache[name]` is missing, and otherwise returns `entry.state, entry.raw` unchanged. `save` keeps writing both. Keep returning the same `raw` string, so every memo keyed by it stays identical (`marker_memo`, `item_memo`, `use_memo`, the HUD's `row.raw`). Unknown-id pruning still runs on the first read after join. If an online migration step ever writes the key, it must call a small `Q.forget_state(player)` (or rely on the join order).
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Measure:** unmeasured. Before and after, on any seed, with 20 stand-in players and 450 completed plus 15 active quests each (state written by fixture), standing near a quest hub with 5 givers: count `get_string` calls and Lua GC bytes per second over 60 s (`collectgarbage("count")` deltas around the globalsteps), and the step time of the tracker and tag passes.
- **Confidence:** high

### P3-02 | Medium | perf | A Scout's every shot, refund and arrow pickup rebuilds and re-sends the whole Character page

- **Where:** `mods/PLAYER/grug_inventory/bags.lua:180-185` (`quiver_changed`), called from `:211` (`add_to_quiver`, i.e. every `grug_inventory.give` of arrows), `:251`, `:304-306` (`consume_ammo`), `:497`; `mods/PLAYER/grug_inventory/pages.lua:758-763`
- **What:** `quiver_changed` normalizes the quiver and then calls `refresh_character`. While the Character page is the player's selected sfinv page, even with the window closed, that page is then fully rebuilt and sent: stats, armor breakdown, model preview, cloak dropdown, achievements or effects body, gear box and short inventory view. A Scout keeps that page selected naturally, because the quiver and the equip slots are on it. The same full build also follows every arrow refund (`refund_ammo` → `give` → `add_to_quiver`) and every arrow pickup or crafted arrow. This is the still-open PLY-11 of the 2026-10 audit, which rated it Low. The arrow path also includes pickups and refunds, so a shot with a refund costs two builds.
- **Evidence:** `grug_abilities/scout.lua:248-251` consumes per launch through `consume_ammo` → `quiver_changed` (`bags.lua:304-306`). `scout.lua:256-258` refunds through `refund_ammo` → `give` → `add_to_quiver` → `quiver_changed` (`bags.lua:211`). `refresh_character` (`pages.lua:758-763`) has no change test of its own.
- **Proposal:** On the server-side paths (consume, refund, give), mark the page dirty (`context.grug_quiver_dirty = true`) instead of re-sending it, and let the existing 1 Hz poll (`pages.lua:599-618`) flush it with one `set_player_inventory_formspec`. Keep the immediate refresh on the player's own inventory actions (`bags.lua:497`, `unload_quiver`), where the page is open. The total on a closed page may then lag by up to 1 s. Nothing else changes.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Measure:** unmeasured. One stand-in Scout with the Character page selected and the window closed, auto-shooting a training mob for 60 s: count `set_inventory_formspec` calls and bytes sent, and the Lua time in `sfinv.get_formspec`, before and after.
- **Confidence:** high

### P3-03 | Medium | perf | `grug_inventory.give` allocates the whole give order and copies every carried list per dug node and per pickup

- **Where:** `mods/PLAYER/grug_inventory/storage.lua:64-82` (`ordered_slots`), `:92-110` (`cells_of`), `:153-172` (`give`), `:496-501` (pickup), `:535-548` (`core.handle_node_drops` override)
- **What:** Every `give` builds one `{list, index}` table per slot of the give order (main[9..32] plus up to 4×20 bag cells, up to 104), then one cell table per slot, plus `get_list` copies of `main` and each bag list (up to about 104 ItemStack userdata). It then walks them twice. Since Round 70, every non-creative dig (`handle_node_drops`) and every item pickup (`register_on_item_pickup`) runs through it, where builtin used one C++ `inv:add_item("main", …)`. This is the hottest player path in the game (mining, farming, tree felling) and pays roughly 200 tables and 100 userdata per node.
- **Evidence:** `storage.lua:168` `cells_of(inv, ordered_slots(inv))` runs on every call. Callers: `storage.lua:500` (every pickup) and `:542` (every drop of every dug node). rg `grug_inventory.give(` finds 41 call sites in total.
- **Proposal:** Keep the order and the result identical and cut the allocations. (1) Cache the slot order per player and rebuild it only in `apply_bag_resize` and at join. (2) In pass 1 (merge into partial stacks), skip lists where `inv:contains_item(list, ItemStack(name))` is false; that check runs in C++ without allocating. (3) In pass 2 (empty cells), read one list at a time in order and stop at the first list that takes the rest. Write the changed cells as now. Run the existing give and sort fixtures unchanged.
- **Effort:** M · **Risk:** low · **Upgrade class (guess):** compatible
- **Measure:** unmeasured. Use a portable microbenchmark over a stand-in inventory (main 32, four 20-slot bags, half full): 10,000 gives of a stackable node drop and of a non-stackable tool, measuring µs per call and bytes allocated, before and after. In the engine, 10 stand-in players dig a 16×16×4 stone block each; compare the step time.
- **Confidence:** medium (the cost per call is certain; its share of a busy server's step is unmeasured)

### P3-04 | Low | perf | Every crediting kill deep-copies and re-serializes the whole quest state (PLY-10, still open)

- **What:** `credit_kill` copies the full state (`editable` → `table.copy`) and `save` runs `core.serialize` over it, including the ever-growing `completed` set, for every kill that raises a counter. - **Effort:** M · **Risk:** medium · **Upgrade class (guess):** migrate
- **Measure:** As PLY-10: µs and bytes per crediting kill at 50, 200 and 450 completed quests, before and after.
- **Confidence:** high

### P3-05 | Low | perf | Quest marker children get `set_observers` every second even when nothing changed

- **Where:** `mods/PLAYER/grug_quests/npc.lua:419-446`
- **What:** The tag-visibility callback runs once a second for every observed quest giver. It allocates a fresh `partitions` table and calls `child:set_observers(...)` on every existing marker child (up to 8 per giver), even when the observer set is unchanged. Its own caller, `grug_core/tag_carrier.lua`, guards each of its `set_observers` calls with `same_set` (`:311`, `:519-524`, `:534-537`). Engine cost of a redundant `set_observers` not checked.
- **Evidence:** `npc.lua:444` runs `if child and child:is_valid() then child:set_observers(partitions[state] or {}) end` unconditionally; compare with `tag_carrier.lua:519-524`.
- **Proposal:** Keep the last sent set per child (`children[state .. ":set"]`) and call `set_observers` only when `same_set` (or an equivalent local compare) says the set changed. Visible behaviour stays identical.
- **Effort:** S · **Risk:** low · **Upgrade class (guess):** compatible
- **Confidence:** medium

## Backlog notes

- Equipment (`equipment.lua:686-689`) and bag slots (`bags.lua:456-471`) return a number for their own lists. Under OR_SC this ends the chain before the soulbound and bound-skill guards (`grug_housing/soulbound.lua:32`, `grug_skills/bound_items.lua:71`). This is harmless today because no soulbound or bound item carries an equip group or `bagslots`. A future soulbound trinket would slip into a slot.
- `Q.turn_in` re-raises a failed money, XP or turn-in-hook observer with `error(..., 0)` (`state.lua:650-652`) inside `on_player_receive_fields`, which crashes the server after the reward was saved. This is deliberate surfacing, but `grug_core.severe.report` would keep the server up.
- Quest reward placement (`state.lua:576-590`) never uses a Scout's quiver, unlike `give`. No quest rewards arrows today (rg `grug_gear:arrow` in `data/zones` finds nothing).
- `grug_money.add` silently clamps at `MAX` (`init.lua:112`). Trader payouts (`grug_traders/trade.lua:763`, `:829`, `:886`) then lose the excess without a refusal, while the quest turn-in and the deposit refuse instead. At about 214,748 gold this is unreachable in practice.
- `storage.lua:520-530` wraps every item's `on_use` at mods-loaded. A later `override_item(on_use)` by a mod running its own mods-loaded hook afterwards drops the pickup wrapper (load-order trap, compare PLY-08).
- `equipment.lua:242-245` says the allow callback "fires repeatedly while a stack is dragged around". The engine sends an action only on a drop or click (engine behaviour not checked). The throttle is harmless either way.
- The Character page's 1 Hz poll (`pages.lua:599-618`) runs `home_text` (and in Effects mode `effects_key`, building strings) every second for every player whose selected page is Character, even with the window closed. This is cheap, but it scales with players.
- `trinkets/init.lua:148` reads `get_properties().hp_max` on each qualifying hit while `:166` uses `grug_classes.get_max_hp`. These are two sources for one value.
- `grug_quests/hud.lua:282-319` and `use.lua:349-378` each carry their own copy of the slot scheduler (the atmosphere_zones pattern).

## Good to know

- Duplication and loss paths checked and found safe: `equip_by_shift` (fit-checked with the source cell as the swap leaves it, then writes, then gives with drop-at-feet as the last resort), `unequip_by_shift`, the class-change unequip (give first, leftover back into the slot), the starter grant (flag spent only when something landed), bag resize (fit proven in the allow callback, applied before `set_size`, drop at feet as a fallback), the quiver (`absorb_into_quiver` by counts, never `take_item` to zero), the inbox (admits exactly `room_for`), the trash (Undo through `give`, the rest stays undoable), `grug_money.take_with_inventory` (all-or-nothing with rollback), deposit (`MAX` check before credit), and quest turn-in (`busy` guard, state saved before money and XP, settlement on copies, `set_stack` rollback).
- Shift-click routing relies on `grug_shift` and `grug_inbox` having exactly one slot, so the engine's move-somewhere loop calls the allow callback once (engine behaviour not checked; the design is consistent with `inventorymanager.cpp` as cited in `inbox.lua:5-11`). Do not resize them.
- Allow-callback order inside grug_inventory is deliberate: `hotbars.lua` first (`init.lua:8-10`), then equipment, bags, storage (the belt, dofile'd at the end of `bags.lua`), then inbox. Every callback returns nil for lists it does not own.
- `grug_quality/init.lua:1195-1203` monkeypatches `grug_inventory.equipment_changed`. Internal calls go through the table field, so the wrapper is honoured. Anyone who caches a local reference to `equipment_changed` would bypass grug_quality's cache drop.
- Quest state rules hold: no reader writes into a `load` table (all mutators use `editable`). `marker_states` is the one marker source (`npc.lua:428`, `grug_map/providers.lua:124`, `minimap.lua:378`). Kill credit and quest drops exit early (`credit_kill` copies only when a counter rises; `roll_quest_drops` returns on one set lookup).
- Inventory window re-sends, for a later perf lane: `refresh_character` on equipment change (not wear), status-modifier change, level change, quiver change (P3-02), guild and housing changes (their own calls), and the 1 Hz poll. `refresh_inventory_page` on every money change and trash event. `grug_inventory.refresh` (`set_page`) on bag-slot changes and grug_jobs state changes. Hotbar switch, `set_player_inventory_formspec`.
