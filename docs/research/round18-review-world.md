## High

1. **Evade reacquisition restarts the return timeout indefinitely.** `mods/ENTITIES/grug_mobs/aggro.lua:24` seeds `grug_damage_at` even while `temp.grug_evading` is active, and `:365` expires that clock by invoking `leash_reset` again. Concrete scenario: a returning ambient monster is blocked by terrain with an eligible guard still nearby. Repeated NPC acquisition causes a new reset every roughly 16 seconds, overwriting `grug_evading.started` before the 40-second fallback can fire. The monster remains untouchable indefinitely. A bounded LuaJIT reproduction loading production aggro completed 60 simulated seconds with `grug_evading.started=48` rather than the original 0. Prevent pursuit-clock creation/timeout processing during an active return, and add a regression covering repeated NPC/group acquisition while the return is blocked. Preserve normal reacquisition after arrival.

Thus ordinary entities fail this filter, `allowed` remains zero, and `:59` fails at the first point. Use real captured registration metadata or an existing level authority API instead of nonexistent prototype fields. While correcting this bounded probe, ensure its population claims use the registered spawn-row host intersection and species-specific predicate: `spawn_policy_allows` alone does not include the Husk's Sunscar L7 check or host eligibility. Merely removing the bad filter would let critters or ineligible-host species satisfy the nonempty-roster assertion and still not prove the requested final eligibility boundary.
