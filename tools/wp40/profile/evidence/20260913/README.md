# 2026-09-13 tree correction and real-engine profiling evidence

The package contract and interpretation are in
[the follow-up record](../../../../../docs/research/wp40-mapgen-profile-tree-fix.md).
`comparison.tsv` is generated by `tools/wp40/profile/compare.py`; it checks
identical engine/harness identities and full output digests before computing
medians. `corrected`, `optimized` (prepared prefix + heap), and `final` (plus
bounded numeric frames) each have three independent fresh-world runs. The
prefix-only diagnostic has one. Every full run includes a disk-only restart.

`baseline/` is the original game before the tree correction; `stage/` is the
supplemental coarse stage measurement, whose instrumentation perturbs LuaJIT
traces. They are diagnostic evidence, not members of the final A/B medians.
Each result includes raw logs, callback/probe events, profiler output, config,
engine/environment identity and exact snapshot/harness SHA manifests. The
original stage snapshot also contains inert `.orig`/`.rej` files from repairing
its disposable instrumentation patch; they are listed in its manifest and are
not loaded by the engine or present in the full comparison snapshots.

To reconstruct a measured game, archive `game.conf`, `minetest.conf`, and
`mods` from base commit `ddf4d6e67057d92852031ebb3e9688b31f5a5e59` into a
disposable directory, then apply the matching `variants/*.patch` with `patch
-p1`. Keep the `final` variant distinct from the earlier `optimized` variant:
only final includes the runtime-constructor seam check and numeric-frame cache.
Use the retained `measurement-harness.tar` in a separate disposable root; it
contains the exact `tools/wp40/profile` inputs shared by all full A/B runs.
Point its runner at the reconstructed game archive with
`WP40_PROFILE_GAME_ARCHIVE`, `WP40_PROFILE_FULL_DIGEST=1`,
`WP40_PROFILE_DEDICATED=1`, and a new absolute output directory. Use the same
engine image and container limits recorded in the package contract. Archive
mtimes do not establish content identity; compare snapshot file hashes.

The current repository harness adds explicit garbage collection between the
post-timing digest arrays and rebases the optional stage patch. Those later
tool revisions are not silently substituted into the frozen A/B evidence.

`final-micro/` records the single final-byte PUC/LuaJIT process pair, input
manifest, interpreter versions and byte-identical outputs. Static receipts and
LuaJIT resource/forward/reverse regressions accompany it. SHA paths in receipts
retain their original execution locations; their contents are copied here
without rewriting the receipts. `files.sha256` binds the stored evidence files
(excluding itself). Reviewers inspect this evidence rather than rerunning PUC.
